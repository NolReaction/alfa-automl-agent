# Ранняя остановка boosting внутри разрешённого fit

`agent/boosting_candidate.py` — отдельный кандидат для CatBoost и LightGBM.
Он выбирает число итераций на дополнительном разбиении **только X_fit/y_fit**,
затем обучает новую обычную pipeline на всех переданных fit-строках. Внешняя
INNER/outer оценка и публикация остаются у host.

```python
recipe = make_boosting_recipe(
    ordinary_recipe, explicit_validation,
    max_iterations=2000, stopping_rounds=50,
)
source = candidate_source()
```

Нужен один обычный рецепт с `action="catboost"` или `"lightgbm"`, проверенной
`model_config` и нормализованной `feature_config`. Ансамбль и преобразованный
`log1p` target не поддерживаются. Политика разбиения обязательна: `random`,
`grouped` для классификации либо `time` для регрессии. `auto`/`None` не
подменяются случайным разбиением. Фабрика принимает 50–2000 итераций и
1–200 stopping rounds, не больше максимального числа итераций.

## Жизненный цикл одного вызова

1. Проверяются task/metric/schema, конечный deadline из host context и исходный
   рецепт. Внешний `phase` не участвует в выборе алгоритма или настроек.
2. Существующий `split_rows` делит только переданные fit-строки. Для
   классификации каждый объявленный класс должен остаться в обеих внутренних
   частях. Невозможная политика даёт явный отказ кандидата.
3. `FeatureTransformer` обучается на внутренней обучающей части. LightGBM
   дополнительно получает `_LightGBMFrame`, категории которого также изучаются
   только на этой части. Невиданные внутренние validation-категории становятся
   missing; словарь не дообучается на них или на X_predict.
4. Native boosting обучается с eval set и early stopping. CatBoost использует
   native категориальные признаки. LightGBM получает явно закодированные
   классы и callback, который считает зарегистрированную host-метрику.
5. Выбранное число деревьев ограничивается минимумом 50, согласованным с
   `model_config`. Недостоверное число итераций вне разрешённых границ
   отклоняется. Создаётся **новая** pipeline `build_pipeline`, её preprocessing
   и модель обучаются заново на **всех X_fit/y_fit**.
6. Возвращаются предсказания X_predict. Для классификации вероятности
   переставляются в объявленный literal class order, после чего при необходимости
   применяется argmax. Строки `"01"`, `"NA"`, `"class c"` остаются метками.

Native CatBoost Macro F1 и Weighted F1 считаются через TotalF1 с отключёнными
весами в оценке, Accuracy — также без весов в оценке. Для ROC AUC CatBoost
использует явно названный Logloss/MultiClass proxy: его multiclass AUC-варианты
не подменяются именем host OVR AUC. MSE использует эквивалентное ранжирование
по RMSE. LightGBM callback непосредственно считает требуемую host-метрику.
Окончательный допуск всегда основан на отдельном пересчёте host.

Для CatBoost до внутреннего обучения проверяются native budgets по разрешённым
fit-признакам: суммарно не более 4096 категорий и 5 млн category cells. Проверка
по исходной cardinality консервативна даже при rare-category grouping.
При превышении кандидат пропускается, вместо несогласованного ordinal encoding
в обучении и eval set. X_predict не участвует в этой проверке.

## Время и диагностика

Для внутреннего обучения отводится не более 30% оставшегося worker-бюджета;
доля уменьшается при дорогом по размеру полном refit. CatBoost callback и
LightGBM callback останавливают внутреннее обучение по этому deadline между
итерациями. Это не прерывание одной нативной итерации посередине: жёсткий
дедлайн процесса по-прежнему обеспечивает host.

Перед полным refit повторно проверяется deadline и оценка стоимости по
измеренной длительности, числу выполненных итераций и отношению размеров fit.
Оценка имеет запас, но не гарантирует линейного масштабирования. Если времени
недостаточно, кандидат завершается ошибкой без изменения ранее принятого CSV.

Сгенерированный source записывает новый `boosting_evidence.json` в отдельном
invocation-каталоге. Там только диагностические counts, policy, best/selected
iterations, измеренная длительность и негарантированная оценка refit. Это не
новый источник оценки качества и не замена native receipt. Файл создаётся
эксклюзивно, без перезаписи существующего пути. Прямой вызов
`execute_boosting_candidate` файлы не пишет; `return_evidence=True` возвращает
ту же диагностику отдельным объектом.

`best_iteration` в evidence — **число итераций с единицы** для обоих backend;
нулевой CatBoost best index преобразуется явно. `internal_iterations` отмечает
число реально наблюдённых callback-итераций, либо консервативный best count,
если backend/spy не предоставил callback progress. Здесь нет warm start и
сэмплирования строк. Pure fit-spy tests проверяют контракты; фактическое
улучшение качества требует отдельного native paired experiment.
