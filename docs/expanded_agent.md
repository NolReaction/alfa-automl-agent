# Расширенный агент: границы и проверка

Один запуск получает условие, словарь столбцов, train/test и образец ответа. Он
сохраняет ранний пригодный CSV, сравнивает семейства моделей и параметры,
проверяет финалистов и обучает выбранное решение на всех строках train.
LLM-режим дополнительно генерирует и исполняет новые гипотезы.

## Описание задачи

`agent/task_spec.py` хранит неизменяемый `TaskSpec`: входные файлы, ID, цель,
признаки, метрику, классы и точные выходные столбцы. Метрика объявляется в
`task.md`, например `Primary metric: LogLoss` или `Метрика оценки — RMSE`.
Словарь с полями `feature,role,dtype` и четыре CSV остаются обязательными.
Имена файлов фиксированы; вложенная папка определяется автоматически.

| Метрики | Тип задачи | Ответ | Лучше |
| --- | --- | --- | --- |
| RMSE, MAE, MSE | Регрессия | Одно конечное число на строку | Меньше |
| R2 | Регрессия | Одно конечное число на строку | Больше |
| Macro F1, Weighted F1, Accuracy | Классификация | Исходная метка класса | Больше |
| ROC AUC | Классификация | Вероятности | Больше |
| LogLoss | Классификация | Вероятности | Меньше |

Числовые `0/1` при метрике классификации остаются метками. `NA`, `01` и `1`
сохраняют исходное написание. Один столбец вероятности для бинарной задачи
требует `Positive class: ...`, точного имени класса в заголовке либо стандартных
меток `0/1` (положительный класс `1`). Несколько столбцов вероятностей должны
точно называться как классы. Порядок образца сохраняется независимо от порядка
`model.classes_`. Для многоклассового ROC AUC требуются явные `OVR` и `macro`.
Неизвестная метрика не подменяется RMSE или F1.

Это поддержка табличных задач с одной целью. Изображения, произвольные архивы,
несколько целей и специализированное прогнозирование временных рядов требуют
отдельных адаптеров. Поля с датами и история объектов сами по себе не превращают
табличный регрессор в универсальную модель временных рядов.

## Модели и признаки

Портфель: RandomForest/HistGradientBoosting, ExtraTrees, CatBoost 1.2.8,
LightGBM 4.6.0, LogisticRegression/Ridge. CatBoost обрабатывает категории
нативно; при высокой мощности категорий действует ограниченный ordinal fallback.
LightGBM получает категории, известные только обучающему fold. Линейные модели
используют разреженное кодирование с ограничением числа категорий.

`agent.features.FeatureTransformer` умеет добавлять индикаторы пропусков,
объединять редкие категории, извлекать части явно указанных дат, длину/число
слов текста и применять signed log к числам. Словарь редких категорий обучается
только на fit-части. Полнотекстовая семантическая модель сюда не входит.

История доступна отдельно через `PastOnlyHistory` и явный `history_config`
в `build_pipeline`. Нужно указать ключ объекта и столбец времени; их нельзя
надёжно угадывать из любого ID. Признаки истории используют ответы только
из строго более ранних периодов обучающей части. Строки одного периода не
видят ответы друг друга. При отсутствии истории есть отдельный флаг;
среднее для подстановки также берётся только из более ранних обучающих строк.
Этот адаптер не заменяет проверку экспериментов Мурада и не включает его ветку.

## Как расходуется бюджет

1. Быстрая линейная модель проходит внешний holdout и полное обучение.
   Проверенный CSV сохраняется сразу.
2. Внутри обучающей части создаётся ещё одно разбиение по той же схеме:
   случайное, по группам дублей либо по времени. Внешние ответы не участвуют
   в выборе параметров.
3. Восемь исходных вариантов исследуют семейства. Затем до шести дополнительных
   конфигураций уточняют два лучших семейства по внутренней метрике.
4. В коротком списке сначала выбираются лучшие представители разных семейств
   по внутренней метрике; дополнительные варианты одного семейства добавляются
   только при нехватке других. Этот список проходит внешний holdout: сначала
   проверяются более быстрые кандидаты по измеренному времени внутреннего
   обучения, чтобы их неиспользованное время досталось следующим. Состав списка
   и общий лимит проверки от этого не меняются. Для двух лучших проверяется один
   заранее заданный blend 50/50: среднее регрессионных прогнозов или выровненных
   вероятностей классов. Веса не подбираются на внешних ответах.
5. Победитель переобучается на полном train. Если переобучение не удалось,
   сохраняется предыдущий пригодный результат. Четверть времени отведена
   финальной фазе; число завершённых попыток зависит от фактической скорости.

Это ограниченный адаптивный перебор по заданным пространствам параметров.
Optuna установлена для программируемых экспериментов, но автоматический поиск
не выдаётся за TPE или pruning. Кандидаты исполняются последовательно с лимитом
до восьми вычислительных потоков. Невозможность внутреннего разбиения явно
фиксируется; скрытого перехода к подбору на внешней проверке нет.

`selection_metric` относится к внутреннему подбору, `metric` /
`verification_metric` — к внешней проверке. Они не взаимозаменяемы.
Внешний holdout тоже используется для выбора среди финалистов и поэтому не
является независимой итоговой оценкой качества. Проверка на нескольких
разбиениях нужна дополнительно; окончательную оценку даёт скрытый test.

## Исследование и ресурсы

Qwen получает описание задачи, известный лучший результат, оба разбиения,
историю гипотез, ошибки, диагностику классов/групп, время и измеренные ресурсы.
Решение о принятии принимает управляющий код по предсказаниям. Самостоятельно
напечатанная моделью метрика не учитывается. Повтор уже упавшего кода не
исполняется; три подряд ошибки завершают исследование с сохранением принятого
CSV. Файлы `run.json` и `research_journal.json` позволяют разобрать решение.
Стоимость в рублях неизвестна; сохраняются только возвращённые API токены.

Монитор отслеживает дочерние процессы по PID и времени создания, включая
потомков, создавших отдельную сессию. При таймауте или превышении суммарного
RSS 28 GiB известные процессы останавливаются. Измерение — каждые 50 мс;
общие страницы могут учитываться несколько раз. Это не жёсткая песочница ОС:
мгновенный fork с завершением родителя между опросами может остаться незамеченным.
При недоступной инспекции процессов память не показывается как измеренная.

## Воспроизводимое сравнение

```powershell
.\.venv\Scripts\python.exe benchmark_models.py data/regression/task.md --time-column Year_Factor --output runs/rolling-models
.\.venv\Scripts\python.exe benchmark_models.py data/classification/task.md --output runs/grouped-models
```

Папка `--output` должна быть новой. Скрипт сравнивает заранее объявленные
пять семейств на последних трёх периодах или пяти grouped fold, сохраняет
конфигурации, отпечатки строк, длительность и предсказания каждой попытки.
Он не меняет `submission.csv` и входные данные. Это сравнение базовых
конфигураций, а не повтор полного автоподбора на каждом fold.
