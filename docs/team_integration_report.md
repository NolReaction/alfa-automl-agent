## Изменение протокола

V2 воспроизведён на локальной фикстуре: объявленный train содержал outer-target,
а результат внешней оценки мог стать обратной связью следующему запросу.
Проверка CSV сама по себе не устраняла это подглядывание.

V3 для девяти поддерживаемых метрик:

1. Host фиксирует исходную схему, классы, outer split, ID и ответы.
2. `ResearchWorkspace` создаёт только outer-fit представление. Исследовательские test/template являются внутренней feature-выборкой, исходные outer/test данные не копируются.
3. Стартовый существующий AutoML работает на этом представлении с явно переданной time/group/random политикой. Все его оценки здесь являются selection.
4. Исследователь пишет гипотезу, JSON-рецепт и `fit_predict(X_fit, y_fit, X_predict, context)`. Host копирует код/рецепт, запускает отдельный процесс на inner fit/validation, проверяет predictions-only CSV и считает inner score.
5. Лучший inner рецепт фиксируется до outer. После завершения диалога host оценивает заранее фиксированные baseline/candidate. Новых API-запросов после этого нет.
6. При выборе кандидата сначала refit/publish проходит baseline, затем кандидат. Неудачный candidate refit сохраняет допущенный baseline побайтно. Без действительно принятого CSV успешный статус невозможен.

Код и рецепт неизменны между inner/outer/refit. Каждое исполнение получает
новые входы, nonce и receipt. Хеши входов, результата и receipt проверяются;
метрика считается по тем же закреплённым байтам результата. Outer actuals
не записываются в процесс прогноза. Evidence с actual формирует только host
после завершения диалога. Ошибка необязательной копии evidence не меняет
метаданные уже опубликованного результата.

Отчёт хранит `research_protocol_version`, шесть стадий, `evaluations.selection`,
`evaluations.final_check`, обе внешние оценки, хеши, provenance и публикацию.
Выбор baseline/candidate использует outer: оценка победителя **не объявляется
несмещённой независимой оценкой системы**. Для этого нужен дополнительный
неиспользованный тест либо платформа.

Старые v2 отчёты читаются с прежним происхождением. Неизвестная метрика
направляется в явно помеченный legacy v2 quality-unverified путь, без гарантий v3.

## Alfa Lab и процессы

Панель показывает подготовку, внутренние эксперименты, фиксацию рецепта,
внешнюю проверку, полное обучение и результат. Видны назначение метрик,
гипотеза/семейство/время попытки, нормальный `not_better`, fallback и неизвестный
usage. Импортированный отчёт не становится локально проверенным.
Сохранились запуск, остановка, просмотр кода/stdout/stderr и выгрузки.
Явная гипотеза из поля Alfa Lab передаётся в v3 как ограниченный совет.

Полный локальный app gate обнаружил несовпадение PID namespace с mounted
`/proc`: supervisor проверял наличие `/proc`, но считал его подходящей
инвентаризацией. Теперь supervisor/jobs проверяют `/proc/self` против текущего
PID перед чтением идентичности или перечислением потомков. При несовпадении
сгенерированные команды не запускаются через supervisor; фиксированные
offline entry points сохраняют ограниченный fallback без обещания полной
инвентаризации потомков. Обычный Windows/Linux путь не отключён.
Запускатель EXE и его исходники не менялись; статическая проверка EXE выполнена.

## Время, память и API

Сохраняются deadline, максимум 8 потоков, отдельные процессы и измеряемый
порог суммарного RSS 28 GiB. Это sampled best-effort контроль, не жёсткий
OS memory cap. Локальная среда не предоставляет подходящую инвентаризацию
PID, поэтому числовой peak RSS здесь неизвестен; он не приравнивается к нулю.
Доступность измерений и execution flags записываются в отчёты исполнений.

Host guard применяется до запроса: число попыток ограничено max_steps,
полный очищенный messages JSON ограничен 64 KiB, оценочный суммарный объём
ограничен 100000 с резервом 4096 output tokens на запрос. Формула оценки:
`ceil(UTF-8 bytes / 3) + 4096`; это не provider usage и не денежная стоимость.
Usage учитывается даже у полученного malformed envelope; неизвестный usage
остаётся неизвестным. Quota/API error не вызывает retry-loop.

**Платный API этой сессией не вызывался: 0 реальных запросов.** Все SDK проверки
использовали localhost и фиктивные ключи. Командный остаток 600 ₽/сутки
неизвестен. Реальный Qwen с новым v3 ещё нужно отдельно проверить ограниченным
согласованным smoke; старый реальный toy v2 не выдаётся за такую проверку.

## Качество и ограничения

Новые public/private баллы и полноразмерные RMSE/Macro F1 этим этапом не
измерялись. Синтетическая линейная задача подтверждает протокол, а не рост
конкурсного качества. Исторические public результаты в handoff не меняются.

Раздельное представление защищает обычный разрешённый путь исследования,
но Python под тем же пользователем способен искать другие файлы. Полноценной
OS-песочницы нет. AST-запреты не используются как доказательство изоляции.

Свободный текст исходного task.md не переносится автоматически: поддержан
явный табличный CSV/schema/metric контракт и bounded гипотеза Alfa Lab.
Дополнительные нестандартные ограничения задачи требуют отдельного адаптера.

Модули policy/portfolio/history из новых заданий ожидают PR владельцев.
Отчёт прямо помечает их как not_connected/disabled. Они не заменены вторыми
реализациями. Порядок будущего подключения: policy → portfolio → history,
отдельные проверяемые коммиты и явное включение; без автоматического расширения
бюджета поиска.
