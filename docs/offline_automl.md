# Автоподбор без API

`solution.py` по умолчанию сравнивает четыре конфигурации моделей и сохраняет лучший проверенный CSV этого запуска. Для обучения нужны локальные данные и зависимости проекта; ключ Qwen не нужен. В Alfa Lab это действие называется **«Автоподбор»**.

## Запуск

Команды из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md
.\.venv\Scripts\python.exe solution.py data/classification/task.md
```

По умолчанию выделяется 600 секунд на весь подбор. Лимит можно изменить, например до 20 минут:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --time-budget 1200
```

Максимум — 10 500 секунд, или 175 минут. Кандидаты запускаются последовательно в отдельных процессах. Оставшееся время делится между оставшимися попытками, поэтому одна долгая модель не должна занять весь запуск. Если все четыре попытки закончились раньше лимита, программа сразу завершает работу.

На macOS/Linux замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

## Какие задачи поддерживаются

В папке задачи должны находиться `task.md` и ровно один комплект `train.csv`, `test.csv`, `data_dictionary.csv`, `sample_submission.csv`; CSV могут быть во вложенной папке. Словарь задаёт один идентификатор, одну цель и типы признаков. ID сохраняются в порядке `test.csv`.

| Тип цели в словаре | Основная метрика | Что лучше |
| --- | --- | --- |
| `numeric` — регрессия | RMSE на исходной шкале | Меньше |
| `category` — классификация | Macro F1 | Больше |

Основная метрика должна быть явно объявлена в условии, например `Метрика оценки — RMSE` или `Основная метрика — Macro F1`. Поддерживаются также `Metric: RMSE` и `Primary metric: Macro F1`. Дополнительные метрики можно описывать отдельно. Отсутствующее, противоречивое или неподдерживаемое объявление приводит к понятной ошибке: тип цели сам по себе не задаёт нужную метрику.

Этот режим использует фиксированный набор моделей и правил обработки. Поддержка другой метрики, нестандартного формата или новых семейств моделей требует изменения кода. Обязательность LLM/API для конкурсной сдачи нужно сверить с техническим заданием организаторов; работоспособность offline-режима этого не устанавливает.

## Как выбирается проверка

По умолчанию действует `--validation auto`:

| Данные | Выбор |
| --- | --- |
| Классификация, есть одинаковые строки признаков | Групповой holdout: дубли не пересекают границу обучения и проверки |
| Классификация без дублей | Случайная проверка 80/20 со стратификацией |
| Регрессия, найден однозначный числовой период с более поздними значениями в test | Последний период train — проверка, более ранние — обучение |
| Остальная регрессия | Случайная проверка 80/20 |

Для распознавания периода нужны одновременно подходящее имя признака, конечные числовые значения без пропусков, от 2 до 100 периодов в train и все значения test позднее train. Это эвристика; причина выбора сохраняется в отчёте. Если подходят несколько столбцов, требуется указать нужный. В групповой проверке все классы должны присутствовать в обеих частях; если это невозможно, программа сообщает ошибку, сохраняя прежний CSV.

Схему можно задать явно:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --validation time --time-column Year_Factor
.\.venv\Scripts\python.exe solution.py data/classification/task.md --validation grouped
.\.venv\Scripts\python.exe solution.py data/classification/task.md --validation random
```

Используется одна фиксированная проверочная выборка, а не среднее нескольких CV-разбиений. Заполнение пропусков и кодирование категорий обучаются только на обучающей части. Все четыре конфигурации получают одинаковые строки проверки. Временные и групповые оценки сравнивайте только с результатами на той же схеме и тех же строках; прежние случайные оценки `44.651289` и `0.619640` относятся к другой проверке.

## Какие модели пробуем

| Попытка | Регрессия | Классификация |
| --- | --- | --- |
| 1 | Стандартный HistGradientBoosting | Стандартный RandomForest |
| 2 | Стандартный ExtraTrees | Стандартный ExtraTrees |
| 3 | HistGradientBoosting с большей ёмкостью | RandomForest с большей ёмкостью |
| 4 | ExtraTrees: 200 деревьев, минимум 1 строка в листе | ExtraTrees: 200 деревьев, минимум 1 строка в листе |

Точные параметры каждой попытки сохраняются в отчёте. Seed — 42, вычислительные потоки ограничены восемью. Более ёмкая модель может оказаться хуже; порядок попыток не означает их ожидаемое место в рейтинге.

Для каждого успешно завершённого кандидата управляющий процесс проверяет ID и правильные ответы holdout, пересчитывает метрику по предсказаниям и проверяет итоговый CSV. Победитель меняется только при строгом улучшении; при равенстве остаётся предыдущий. Финальные предсказания каждого кандидата получаются после переобучения на всех строках train.

## Проверка на публичных данных, 20 октября 2026

Обе задачи прошли все четыре попытки с `--validation auto`, Python 3.12 и зависимостями из `requirements.txt`. Для регрессии автоматически выбран `Year_Factor`: периоды 1–4 в обучении, 5 — в проверке (18 308 строк). Для классификации выбраны группы одинаковых признаков: 17 515 проверочных строк, пересечение групп — 0.

| Попытка | Регрессия, RMSE ↓ | Классификация, Macro F1 ↑ |
| --- | --- | --- |
| Стартовая модель | 49.206622 | **0.593601** |
| ExtraTrees | 47.914055 | 0.588912 |
| Стартовая модель с большей ёмкостью | 54.302202 | 0.586843 |
| ExtraTrees: 200 деревьев, лист из 1 строки | **47.789053** | 0.566810 |

В регрессии выбран четвёртый кандидат, в классификации сохранён первый: более поздние попытки оказались хуже. Итоговые CSV прошли проверку формата, метрики независимо пересчитаны по сохранённым holdout-предсказаниям, исходные файлы не изменились. Обе задачи использовали 0 API-вызовов. Это локальная проверка, не баллы платформы; прежний лучший результат команды здесь воспроизведён, новый рекорд не заявляется.

## Результат и ошибки

В терминале успешный запуск записывает `submission.csv` рядом с `task.md`. Это лучший результат **среди попыток текущего запуска**. Существующий CSV не участвует в сравнении: его качество без соответствующего проверочного отчёта неизвестно.

В `.agent_runs/<номер запуска>/` сохраняются:

- `automl_report.json` — схема, параметры, метрики и статусы попыток, выбранный победитель, время и ноль API-вызовов;
- `holdout_predictions.csv` — проверочные ID, правильные ответы и предсказания победителя;
- отдельные папки попыток с их результатами и журналами.

Для классификации отчёт победителя также содержит `classification_diagnostics`: матрицу ошибок, precision/recall/F1 и количества по классам, accuracy и Macro F1. Эти значения вычисляются из проверочных предсказаний; направление матрицы — истинные классы по строкам, прогнозы по столбцам. Диагностика необязательна: для задач более чем с 50 классами или слишком длинными метками подробный блок пропускается, обучение продолжается. Схема проверки и правило выбора победителя от добавления диагностики не меняются.

| Ситуация | Что происходит |
| --- | --- |
| Все попытки обработаны, есть успешный кандидат | Сохраняется лучший проверенный CSV |
| У следующей попытки ошибка, битый CSV или худшая метрика | Победитель сохраняется; причина видна в отчёте |
| Достигнут лимит времени, есть успешный кандидат | Сохраняется лучший из завершённых, в отчёте отмечается `time_limit` |
| Ни одного проверенного результата | Ненулевой код завершения; прежний CSV остаётся на месте |

В Alfa Lab подбор работает на копии данных и показывает таблицу попыток. Текущий CSV задачи меняется только после **«Использовать CSV»**. Победителя можно сравнить с одиночными baseline/ExtraTrees при совпадающих данных, метрике и фактической проверке. Успешный подбор не гарантирует улучшение прежнего рекорда команды или результата скрытого теста.

## Где остался Qwen

Исследование с генерацией Python-кода запускается явно:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --mode llm
```

Для него нужны параметры API в `.env`. В панели это отдельное действие Qwen. Параметры `--validation` и `--time-column` относятся только к offline-режиму.

Цикл Qwen пока сохраняет последний структурно корректный CSV. Гарантия выбора лучшего по пересчитанной метрике относится к фиксированным кандидатам автоподбора. Для конкурсной сдачи выбираем режим после проверки требований организаторов и полного запуска итогового архива.
