# Автоподбор без API

`solution.py --mode offline` сравнивает семейства моделей и уточняет параметры лучших и сохраняет лучший проверенный CSV этого запуска. Для обучения нужны локальные данные и зависимости проекта; ключ Qwen не нужен. В Alfa Lab это действие называется **«Автоподбор»**. Конкурсный режим по умолчанию — `auto`: при наличии настроек API в окружении он включает LLM. Для гарантированного запуска без API используйте команды ниже.

## Запуск

Команды из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --mode offline
.\.venv\Scripts\python.exe solution.py data/classification/task.md --mode offline
```

По умолчанию выделяется 600 секунд на весь подбор. Лимит можно изменить, например до 20 минут:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --mode offline --time-budget 1200
```

Максимум — 10 500 секунд, или 175 минут. Кандидаты запускаются последовательно в отдельных процессах. Попытки получают часть оставшегося времени; четверть общего бюджета резервируется для финального обучения. Начальный проверенный CSV сохраняется до окончания поиска. Если запланированные попытки закончились раньше лимита, программа сразу завершает работу.

На macOS/Linux замените `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

## Какие задачи поддерживаются

В папке задачи должны находиться `task.md` и ровно один комплект `train.csv`, `test.csv`, `data_dictionary.csv`, `sample_submission.csv`; CSV могут быть во вложенной папке. Словарь задаёт один идентификатор, одну цель и типы признаков. ID сохраняются в порядке `test.csv`.

| Задача | Метрика | Ответ |
| --- | --- | --- |
| Регрессия | RMSE, MAE, MSE — меньше; R2 — больше | Числа |
| Классификация | Macro F1, Weighted F1, Accuracy — больше | Исходные метки |
| Классификация | ROC AUC — больше; LogLoss — меньше | Вероятности |

Основная метрика явно объявляется в условии: `Metric: MAE`, `Primary metric:
LogLoss` или `Метрика оценки — RMSE`. Она определяет тип задачи, поэтому
числовые метки классов не становятся регрессией. Неизвестное или противоречивое
объявление вызывает понятную ошибку. Вероятности выравниваются по именам классов
и шаблону ответа. [Полный контракт и ограничения](expanded_agent.md).

Автоподбор не обращается к LLM. Официальный кейс требует также генерацию кода
и исследование гипотез; это выполняет отдельный режим Qwen.

## Как выбирается проверка

По умолчанию действует `--validation auto`:

| Данные | Выбор |
| --- | --- |
| Классификация, есть одинаковые строки признаков | Групповой holdout: дубли не пересекают границу обучения и проверки |
| Классификация без дублей | Случайная проверка 80/20 со стратификацией |
| Регрессия, найден однозначный числовой период с более поздними значениями в test | Последний период train — проверка, более ранние — обучение |
| Остальная регрессия | Случайная проверка 80/20 |

Для распознавания периода нужны одновременно подходящее имя признака, конечные числовые значения без пропусков, от 2 до 100 периодов в train и все значения test позднее train. Это эвристика; причина выбора сохраняется в отчёте. Если подходят несколько столбцов, требуется указать нужный. В групповой проверке все классы должны присутствовать в обеих частях; если это невозможно, программа сообщает ошибку, сохраняя прежний CSV.

Схему можно задать явно:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --mode offline --validation time --time-column Year_Factor
.\.venv\Scripts\python.exe solution.py data/classification/task.md --mode offline --validation grouped
.\.venv\Scripts\python.exe solution.py data/classification/task.md --mode offline --validation random
```

Внешняя проверочная выборка фиксируется один раз. Внутри оставшихся обучающих строк создаётся отдельная выборка для подбора параметров по той же схеме. Если такое вложенное разбиение невозможно, сохраняется начальная модель без адаптивного подбора. Заполнение пропусков и кодирование категорий обучаются только на обучающей части. Все кандидаты подбора получают одинаковую внутреннюю выборку; финалисты — одинаковую внешнюю. Временные и групповые оценки сравнивайте только с результатами на той же схеме и тех же строках; прежние случайные оценки `44.651289` и `0.619640` относятся к другой проверке.

## Какие модели пробуем

| Семейство | Регрессия | Классификация |
| --- | --- | --- |
| Прежний baseline | HistGradientBoosting | RandomForest |
| ExtraTrees | ExtraTreesRegressor | ExtraTreesClassifier |
| CatBoost | CatBoostRegressor | CatBoostClassifier |
| LightGBM | LGBMRegressor | LGBMClassifier |
| Линейное | Ridge | LogisticRegression |

После быстрого линейного старта сравниваются восемь вариантов моделей и
обработки признаков. До шести дополнительных конфигураций уточняют два лучших
семейства по **внутренней** метрике. Во внешнюю проверку попадают до трёх
финалистов с приоритетом разных семейств; ещё одна попытка проверяет фиксированное среднее двух лучших
моделей. Параметры, обработка, причины отказа и время сохраняются.

`selection_metric` — подбор; `metric` и `verification_metric` — внешняя
проверка. Сравнивать эти две колонки между собой нельзя. Финальный holdout
используется для выбора среди финалистов и не является независимым test.

Полное обучение выполняется для стартового CSV и выбранного финального
решения. Внутренние попытки только обучаются на своём fold и предсказывают
проверочные строки. При неудаче полного обучения сохраняется предыдущий
пригодный CSV. Все оценки пересчитывает управляющий процесс по закреплённым
ID и ответам. [Этапы, признаки, ансамбли и ограничения](expanded_agent.md).

Для классификации выбраны группы одинаковых признаков: 17 515 проверочных строк, пересечение групп — 0.

| Попытка | Регрессия, RMSE ↓ | Классификация, Macro F1 ↑ |

Итоговые CSV прошли проверку формата, метрики независимо пересчитаны по сохранённым holdout-предсказаниям, исходные файлы не изменились. Обе задачи использовали 0 API-вызовов. Это локальная проверка, не баллы платформы; прежний лучший результат команды здесь воспроизведён, новый рекорд не заявляется.

## Результат и ошибки

В терминале успешный запуск записывает `submission.csv` рядом с `task.md`. Это лучший результат **среди попыток текущего запуска**. Существующий CSV не участвует в сравнении: его качество без соответствующего проверочного отчёта неизвестно.

В `.agent_runs/<номер запуска>/` сохраняются:

- `automl_report.json` — схема, параметры, метрики и статусы попыток, выбранный победитель, время и ноль API-вызовов;
- `holdout_predictions.csv` — проверочные ID, правильные ответы и предсказания победителя;
- отдельные папки попыток с их результатами и журналами.

Для классификации отчёт победителя также содержит `classification_diagnostics`: матрицу ошибок, precision/recall/F1 и количества по классам, accuracy и Macro F1. Эти значения вычисляются из проверочных предсказаний; направление матрицы — истинные классы по строкам, прогнозы по столбцам. Диагностика необязательна: для задач более чем с 50 классами или слишком длинными метками подробный блок пропускается, обучение продолжается. Схема проверки и правило выбора победителя от добавления диагностики не меняются.

| Ситуация | Что происходит |
| --- | --- |
| Все попытки обработаны, есть успешный кандидат | Сохраняется лучший проверенный CSV |
| У следующей попытки ошибка, битый CSV или худшая метрика | Победитель сохраняется; причина видна в отчёте |
| Достигнут лимит времени, есть успешный кандидат | Сохраняется лучший из завершённых, в отчёте отмечается `time_limit` |
| Ни одного проверенного результата | Ненулевой код завершения; прежний CSV остаётся на месте |

В Alfa Lab подбор работает на копии данных и показывает таблицу попыток. Текущий CSV задачи меняется только после **«Использовать CSV»**. Победителя можно сравнить с одиночными baseline/ExtraTrees при совпадающих данных, метрике и фактической проверке. Успешный подбор не гарантирует улучшение прежнего рекорда команды или результата скрытого теста.

## Где остался Qwen

Исследование с генерацией Python-кода запускается явно:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md --mode llm
```

Для него нужны параметры API в `.env`. В панели это отдельное действие Qwen. Параметры `--validation` и `--time-column` относятся только к offline-режиму.

Для девяти поддерживаемых метрик цикл Qwen тоже использует закреплённые строки проверки: управляющий процесс пересчитывает метрику по новым holdout-предсказаниям и публикует только строгое улучшение. Гипотеза и оба CSV должны быть созданы одним вызовом инструмента; прежние файлы не засчитываются повторно. На неизвестной метрике сохраняется общий LLM-путь с явной отметкой, что качество не проверено независимо. [Подробности конкурсного запуска](platform_submission.md).

Расширенный портфель дополнительно сравнивается на нескольких периодах и grouped fold командой `benchmark_models.py`: [методика](expanded_agent.md#воспроизводимое-сравнение).
