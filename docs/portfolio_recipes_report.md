## Результат

`agent/portfolio_recipes.py` возвращает восемь детерминированных рецептов через согласованный интерфейс:

```python
from agent.portfolio_recipes import portfolio_candidates

candidates = portfolio_candidates(
    {"task_type": "classification", "metric": "Macro F1"},
    available_actions=("baseline", "extra_trees", "catboost", "lightgbm", "linear"),
    limit=8,
)
```

| ID после `portfolio_v1_` | Модель / отличие |
| --- | --- |
| `linear_regularized` | Ridge alpha=10 / LogisticRegression C=0.1 |
| `baseline_conservative` | RF 300 деревьев, листья от 4 / HGB 300 итераций, 15 листьев |
| `et_regularized` | ExtraTrees 300 деревьев, листья от 4, половина признаков |
| `cb_shallow` | CatBoost 500 итераций, глубина 4 |
| `cb_medium` | CatBoost 500 итераций, глубина 7 |
| `lgbm_conservative` | LightGBM 400 деревьев, 15 листьев |
| `lgbm_medium` | LightGBM 500 деревьев, 63 листа |
| `lgbm_representation` | Консервативный LightGBM + индикаторы пропусков и редкие категории |

Полные параметры — в модуле. Конфигурации проверяются существующими `make_model_config` и `normalize_feature_config`. ID стабильны, структуры независимы, результат JSON-совместим. Поставщик не получает данные/ответы/пути, не читает окружение, не обучает модели, не определяет доступность пакетов. Вызывающий передаёт tuple доступных actions; фильтрация происходит до limit. Неизвестные метрики, несогласованный тип задачи, лишние поля, неверные типы, дубли actions и limit вне 1–8 вызывают ValueError; bool не принимается как limit. Пустой список доступных actions допустим после проверки остальных аргументов.

Вызов использует прежние настройки моделей без новых quality options. Файлы общего поиска и приложения не изменены. Для подключения Дима определяет, какие рецепты заменить/добавить в существующий общий бюджет, и дедуплицирует по конфигурации, а не по подписи. Просто добавить восемь дополнительных обучений сверх прежнего лимита нельзя.

## Что проверено

Контракт охватывает все девять зарегистрированных метрик, оба типа задач, неизменность входов, независимость вложенных объектов, JSON round-trip, фильтрацию/порядок, ошибки аргументов и работу без optional модельных пакетов при исключении этих actions. Общая профильная команда ниже завершила **49 тестов успешно за 9.470 секунды**, включая существующие проверки моделей, признаков, поиска и упаковки.

Функциональные проверки реально обучают **все восемь исходных рецептов** на трёх небольших смешанных таблицах: regression, binary classification и multiclass classification. Есть пропуски, полностью пустой числовой столбец, буквальные метки `001`/`NA`, категория только в holdout. Дополнительно проверено, что линейный preprocessing не обучил vocabulary на holdout.

`experiment_portfolio_recipes.py` выполняет ту же техническую проверку в отдельных процессах: последовательно, до 8 потоков, до 30 секунд и 8 GiB на попытку, до 120 секунд на сценарий по умолчанию. Используется существующий `run_python` с остановкой дерева процессов. Результаты пишутся только в новый каталог; существующий не перезаписывается. Таймауты, ошибки, пропущенные по бюджету попытки и ресурсы сохраняются в smoke.json. Для бинарного ROC AUC положительный класс явно `001`.

## Воспроизведение

Из корня репозитория, в активированном окружении проекта:

```bash
python -m unittest tests.test_portfolio_recipes tests.test_models tests.test_features tests.test_search tests.test_build_submission -q
python experiment_portfolio_recipes.py --task-type regression --metric RMSE --out-dir data/experiments/portfolio-recipes/regression
python experiment_portfolio_recipes.py --task-type classification --metric "ROC AUC" --binary --out-dir data/experiments/portfolio-recipes/binary
python experiment_portfolio_recipes.py --task-type classification --metric LogLoss --out-dir data/experiments/portfolio-recipes/classification
```

Для повторного запуска выбрать новый out-dir. На Windows использовать `.\.venv\Scripts\python.exe`, на Linux — `.venv/bin/python` либо активированный `python`. Команды не требуют данных соревнования или API-ключа. Полные CSV и JSON остаются в игнорируемом `data/experiments/portfolio-recipes/`.

## Что это ещё не доказывает

Синтетические цели классификации здесь специально простые технические метки; их баллы не измеряют пользу портфеля. Не проводились nested grouped/time эксперименты на public, fair-budget сравнение с нынешним exploration_plan, абляции представления или финальный refit на больших данных. Улучшение конкурсного качества не заявляется. Поставщик пока не подключён к runtime-поиску; запуск решения остаётся прежним.

Следующий этап Тани/интегратора: зафиксировать одинаковые бюджеты и внешние folds, сравнить оба портфеля с выбором только на inner, включить в стоимость все влияющие на выбор абляции, сохранить предсказания/параметры/ошибки и решить, какие рецепты заслуживают включения. Известные публичные периоды и folds не считать новыми независимыми данными.

## Зафиксированный протокол полного исследования

До первого обучения на новых public-разбиениях фиксируем следующий протокол. Модельные конфигурации и порядок восьми вариантов остаются исходными; результаты smoke не использовались для их изменения. Исследовательский код продолжает жить в четырёх файлах Тани. Общая рабочая ветка другого ИИ и стандартные настройки поиска не изменяются.

- Public classification: `StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=seed)`, внешний fold 0 для seeds **1729 и 2718**. Внутренний split — fold 0 того же splitter/seed только внутри outer-fit. Группы — хеш всех 42 исходных признаков до преобразований, без ID/target. Невозможные splits фиксируются, другие seed/fold вместо них не ищутся.
- Public regression: outer-периоды **3, 4, 5** `Year_Factor`. Inner holdout — последний период внутри прошлого outer-fit, inner-fit — строго предшествующие периоды. После выбора выполняется fresh refit только на outer-fit; полное обучение public train и конкурсная посылка в этот эксперимент не входят.
- Каждый из двух портфелей получает **600 с поиска**, одна попытка — не более **180 с** и оставшегося времени поиска. На финальный refit каждого выбранного рецепта отдельно выделяется **180 с**. Время startup, подготовки попытки и host-пересчёта включается; результат, проверка которого вышла за бюджет, не может выиграть. Сначала `exploration_plan`, затем `portfolio_v1`; оба получают собственный одинаковый deadline.
- Победитель определяется только по завершённой inner-оценке с учётом направления метрики; при равенстве — первый в заранее заданном порядке. Два выбора фиксируются на диске до внешней оценки. Outer не изменяет следующий split, рецепт, вес или бюджет. Неудачный refit остаётся неудачей без выбора другого рецепта по outer.
- Стандартный baseline оценивается отдельно на тех же внешних строках, с самостоятельным лимитом refit 180 с; он не получает бесплатного участия в подборе.
- Четыре **диагностические** абляции conservative LightGBM: без преобразований, только индикаторы пропусков, только rare_min_count=10, оба. Они используют inner, запускаются после фиксации победителей, имеют отдельный лимит **600 с** на серию и 180 с на попытку, не меняют выбранный рецепт. Их стоимость показана отдельно и не выдаётся за бесплатный этап поиска.
- Переносимость: `breast_cancer`, `wine`, `diabetes` из установленного sklearn, seeds **1729/2718**. На портфель — **60 с**, попытка/refit — **30 с**, диагностическая серия — **120 с**. Бинарные/многоклассовые вероятности сохраняются с порядком классов. Дополнительные метрики рассчитываются из тех же файлов, без дополнительных обучений.
- Все обучения последовательные, максимум 8 потоков. Запрошенный предел памяти — **8 GiB**, используется существующий monitor. В текущем окружении PID-inspection недоступен: суммарный RSS/CPU дерева процессов будет помечен unavailable, фактическое соблюдение порога памяти не заявляется. Worker отдельно измеряет свой process CPU time и fit/predict wall time.
- Перед fit пишется manifest с исходным commit, хешами кода/входов/групп/splits, точными конфигурациями, версиями, бюджетами и правилом выбора. Исходники копируются для воспроизведения; хеши проверяются во время попыток и после серии. Все предсказания, ID/actual, warnings, сбои, timeout/OOM и пропуски по бюджету сохраняются. API calls: **0**.

Рабочее окружение экспериментов: **scikit-learn 1.5.2 / NumPy 1.26.4 / pandas 2.2.3**. Это существенно: другая версия sklearn даёт другие SGKF-разбиения при тех же seed. Аудит именно этого окружения подтвердил:

| Seed | Outer fit / hold | Inner fit / validation | Worms: inner validation / outer hold |
| --- | --- | --- | --- |
| 1729 | 69 872 / 17 798 | 55 785 / 14 087 | 7 / 16 |
| 2718 | 70 651 / 17 019 | 56 582 / 14 069 | 11 / 16 |

Все 10 классов присутствуют в каждой части, пересечения групп нулевые. Публичные периоды 3–5 и прежние folds уже изучены командой. Это вложенное сравнение двух фиксированных портфелей, а не независимый private-тест или оценка полного production AutoML с refinement/ensemble. По двум classification и трём зависимым временным folds показываем отдельные пары, диапазон и знаки изменений; убедительную статистическую значимость и обычные интервалы независимых folds не заявляем.
