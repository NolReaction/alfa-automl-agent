## Поставщик и область проверки

Интерфейс: `portfolio_candidates(profile: dict, *, available_actions: tuple[str, ...], limit: int = 8) -> list[dict]`. `profile` содержит ровно `task_type` и `metric`. Возвращаются существующие поля `id`, `action`, `label`, `model_config`, `feature_config`. Конфигурации проходят `make_model_config` и `normalize_feature_config`, сериализуются в JSON без специальных объектов и не разделяют изменяемые вложенные структуры между вызовами. Поставщик не читает данные, пути или окружение, не обучает модели и не определяет доступность пакетов.

Доступные actions задаёт вызывающая сторона; фильтрация сохраняет исходный порядок и предшествует limit. Пустой tuple допустим после проверки остальных аргументов. Неизвестные метрики, несовместимый тип задачи, лишние поля, дубли actions и неверные типы дают `ValueError`; limit — строго целое 1–8, без bool. При исключении CatBoost/LightGBM работает портфель существующих sklearn-моделей.

Поддерживаются девять зарегистрированных метрик: RMSE, MAE, MSE, R2, Macro F1, Weighted F1, Accuracy, ROC AUC, LogLoss. Это проверка контрактов и форматов, а не девять независимых доказательств качества. В измерениях основная метрика — Macro F1 для классификации и RMSE для регрессии; остальные пересчитываются из тех же outer-предсказаний.

Новые ID сокращены только удалением префикса `portfolio_v1_`.

## Разбиения, фиксация выбора и бюджеты

- Public classification: SGKF с 5 частями, shuffle=True, внешний fold 0 для seeds 1729 и 2718. Группы — хеш всех 42 исходных признаков до preprocessing, без ID/target. Inner — fold 0 того же splitter/seed исключительно внутри outer-fit. Все классы должны присутствовать в обеих частях; невозможный fold не заменяется другим.
- Public regression: outer-периоды 3, 4, 5 признака `Year_Factor`; обучение только на более ранних периодах. Inner — последний доступный период outer-fit, его обучение — ещё более ранние периоды. Две новые случайные выборки не создаются поверх времени.
- `breast_cancer` и `wine`: тот же фиксированный grouped-алгоритм, seeds 1729/2718. `diabetes`: зафиксированные 80/20 outer и 80/20 inner только внутри outer-fit. Эти небольшие наборы проверяют переносимость процедуры и контрактов.
- Каждая попытка заново обучает весь preprocessing на fit. Победитель определяется только по завершённым inner-попыткам, с правильным направлением метрики; при равенстве берётся первый в исходном порядке. Оба выбора записываются в `frozen_winners.json` **до любого outer-refit**.
- Outer не меняет следующий split, настройки или бюджет. Неудачный refit не заменяется другой моделью по внешней оценке. При невозможном inner действует заранее заданный первый кандидат; если ни одна внутренняя попытка не завершилась, outer-refit данного портфеля не запускается.
- После фиксации выбранных моделей выполняются четыре диагностические абляции LightGBM на inner: raw, missing_only, rare_only, both. Они не меняют победителей; стоимость серии учитывается отдельно. Это диагностика факторов, а не дополнительный бесплатный этап поиска.

| Ограничение на один split | Public | Наборы sklearn |
| --- | ---: | ---: |
| Поиск каждого портфеля | 600 с | 60 с |
| Одна попытка | 180 с | 30 с |
| Outer-refit каждого победителя | 180 с | 30 с |
| Отдельный baseline-reference | 180 с | 30 с |
| Серия четырёх inner-диагностик | 600 с | 120 с |

Сначала выполняется `exploration_plan`, затем `portfolio_v1`, с отдельными одинаковыми deadline. Время подготовки попытки, запуска subprocess и host-пересчёта входит в поиск; поздно проверенный результат не может выиграть. Общая подготовка входных split-файлов записывается отдельно. Остановка дерева процессов может выйти за deadline — фактическая стоимость сохраняется. Порядок портфелей не рандомизирован, поэтому времена не доказывают универсальное преимущество скорости.

Окружение: Linux, Python 3.12.14, **scikit-learn 1.5.2, NumPy 1.26.4, pandas 2.2.3**, CatBoost 1.2.8, LightGBM 4.6.0, threadpoolctl 3.6.0, psutil 6.1.1. Версия sklearn существенна: другая версия может дать другие SGKF-разбиения при тех же seeds. Модельный random_state остаётся штатным; seeds 1729/2718 относятся к разбиениям.

Все обучения последовательные; model_n_jobs/BLAS/OpenMP ограничены 8, штатный LogisticRegression сохраняет n_jobs=1. Запрошенный лимит памяти — **8 GiB**. В данном окружении PID-inspection недоступен (`process inspection unavailable`): RSS и CPU дерева процессов остаются null, фактическое соблюдение порога памяти не доказано. Worker измеряет собственные fit/predict wall time и process CPU; это не CPU всего дерева. Собственный CPU доступен для всех 253 итоговых попыток, телеметрия дерева недоступна для всех 253.
