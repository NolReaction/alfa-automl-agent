Это первый законченный этап задачи Тани: поставщик конфигураций и проверка исполнимости. Подключение к AutoML и сравнительные эксперименты на public остаются следующим этапом.

## Результат

`agent/portfolio_recipes.py` возвращает восемь детерминированных рецептов через согласованный интерфейс:

```python
from agent.portfolio_recipes import portfolio_candidates

candidates = portfolio_candidates(
    {"task_type": "classification", "metric": "Macro F1"},
    available_actions=("baseline", "extra_trees", "catboost", "lightgbm", "linear"),
    limit=8,
)
```

| ID после `portfolio_v1_` | Модель / отличие |
| --- | --- |
| `linear_regularized` | Ridge alpha=10 / LogisticRegression C=0.1 |
| `baseline_conservative` | RF 300 деревьев, листья от 4 / HGB 300 итераций, 15 листьев |
| `et_regularized` | ExtraTrees 300 деревьев, листья от 4, половина признаков |
| `cb_shallow` | CatBoost 500 итераций, глубина 4 |
| `cb_medium` | CatBoost 500 итераций, глубина 7 |
| `lgbm_conservative` | LightGBM 400 деревьев, 15 листьев |
| `lgbm_medium` | LightGBM 500 деревьев, 63 листа |
| `lgbm_representation` | Консервативный LightGBM + индикаторы пропусков и редкие категории |

Полные параметры — в модуле. Конфигурации проверяются существующими `make_model_config` и `normalize_feature_config`. ID стабильны, структуры независимы, результат JSON-совместим. Поставщик не получает данные/ответы/пути, не читает окружение, не обучает модели, не определяет доступность пакетов. Вызывающий передаёт tuple доступных actions; фильтрация происходит до limit. Неизвестные метрики, несогласованный тип задачи, лишние поля, неверные типы, дубли actions и limit вне 1–8 вызывают ValueError; bool не принимается как limit. Пустой список доступных actions допустим после проверки остальных аргументов.

Вызов использует прежние настройки моделей без новых quality options. Файлы общего поиска и приложения не изменены. Для подключения Дима определяет, какие рецепты заменить/добавить в существующий общий бюджет, и дедуплицирует по конфигурации, а не по подписи. Просто добавить восемь дополнительных обучений сверх прежнего лимита нельзя.

## Что проверено

Контракт охватывает все девять зарегистрированных метрик, оба типа задач, неизменность входов, независимость вложенных объектов, JSON round-trip, фильтрацию/порядок, ошибки аргументов и работу без optional модельных пакетов при исключении этих actions. Общая профильная команда ниже завершила **49 тестов успешно за 9.470 секунды**, включая существующие проверки моделей, признаков, поиска и упаковки.

Функциональные проверки реально обучают **все восемь исходных рецептов** на трёх небольших смешанных таблицах: regression, binary classification и multiclass classification. Есть пропуски, полностью пустой числовой столбец, буквальные метки `001`/`NA`, категория только в holdout. Дополнительно проверено, что линейный preprocessing не обучил vocabulary на holdout.

`experiment_portfolio_recipes.py` выполняет ту же техническую проверку в отдельных процессах: последовательно, до 8 потоков, до 30 секунд и 8 GiB на попытку, до 120 секунд на сценарий по умолчанию. Используется существующий `run_python` с остановкой дерева процессов. Результаты пишутся только в новый каталог; существующий не перезаписывается. После subprocess host повторно читает CSV, сверяет ID/actual с синтетическим fixture, проверяет вероятности и пересчитывает метрику с явным порядком классов. Таймауты, ошибки, пропущенные по бюджету попытки и ресурсы сохраняются в smoke.json. Для бинарного ROC AUC положительный класс явно `001`.

Фактические отдельные CLI-прогоны:

| Сценарий | Завершено | Сумма времени дочерних процессов | API |
| --- | --- | --- | --- |
| Regression / RMSE | 8 из 8 | 7.583 с | 0 |
| Binary / ROC AUC | 8 из 8 | 8.721 с | 0 |
| Multiclass / LogLoss | 8 из 8 | 8.597 с | 0 |

Это технические замеры на данной машине, а не бюджет поиска или оценка скорости на больших задачах. Среда: Linux, Python 3.12.14, NumPy 1.26.4, pandas 2.2.3, scikit-learn 1.5.2, CatBoost 1.2.8, LightGBM 4.6.0, psutil 6.1.1. Локальный Windows-прогон не выполнялся.

## Воспроизведение

Из корня репозитория, в активированном окружении проекта:

```bash
python -m unittest tests.test_portfolio_recipes tests.test_models tests.test_features tests.test_search tests.test_build_submission -q
python experiment_portfolio_recipes.py --task-type regression --metric RMSE --out-dir data/experiments/portfolio-recipes/regression
python experiment_portfolio_recipes.py --task-type classification --metric "ROC AUC" --binary --out-dir data/experiments/portfolio-recipes/binary
python experiment_portfolio_recipes.py --task-type classification --metric LogLoss --out-dir data/experiments/portfolio-recipes/classification
```

Для повторного запуска выбрать новый out-dir. На Windows использовать `.\.venv\Scripts\python.exe`, на Linux — `.venv/bin/python` либо активированный `python`. Команды не требуют данных соревнования или API-ключа. Полные CSV и JSON остаются в игнорируемом `data/experiments/portfolio-recipes/`.

## Что это ещё не доказывает

Синтетические цели классификации здесь специально простые технические метки; их баллы не измеряют пользу портфеля. Не проводились nested grouped/time эксперименты на public, fair-budget сравнение с нынешним exploration_plan, абляции представления или финальный refit на больших данных. Улучшение конкурсного качества не заявляется. Поставщик пока не подключён к runtime-поиску; запуск решения остаётся прежним.

Следующий этап Тани/интегратора: зафиксировать одинаковые бюджеты и внешние folds, сравнить оба портфеля с выбором только на inner, включить в стоимость все влияющие на выбор абляции, сохранить предсказания/параметры/ошибки и решить, какие рецепты заслуживают включения. Известные публичные периоды и folds не считать новыми независимыми данными.
