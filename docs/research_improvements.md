# Развитие Research v3: условия задачи, время и диагностика

Дата: 20 октября 2026. База: `f63223a8ec7f5365ea7a1aacec45d471d30e257b`.
Ветка: `work/dima-research-v2`, PR #11. Код main и отправленное ранее решение
автоматически не меняются.

## Что изменилось

1. Исходное описание задачи сохраняется в очищенном `task_description.md`.
   Исследователь сразу видит первые 4 KiB и указание прочитать полный файл;
   признак полноты явный. Поддержан текст до 256 KiB UTF-8. При превышении
   применяется фиксированный базовый рецепт без AutoML-поиска и обращений к LLM.
   Пути CSV заменяются на разрешённые представления, известные исходные пути
   скрываются, распознанные секреты удаляются. Единицы измерения и отношения
   вроде kWh/m2 и A/B сохраняются. Полный словарь признаков уже переносился
   ранее и продолжает переноситься. Семантический файл проверяется на изменение.
2. Планировщик времени измеряет длительность выполнения замороженных рецептов.
   Минимальный резерв финализации остаётся прежним; при дорогих обучениях
   увеличивается с учётом размеров outer/full train и prediction-наборов.
   При оценочной нехватке времени улучшенная inner-метрика не делает кандидат
   допустимым: причина `refit_budget` записывается в журнал. Отдельные outer/refit
   совместно делят остаток времени, приоритет сохраняет базовый результат.
   Каждый API-запрос получает свежую сводку бюджета.
3. Подготовка CSV, хеширование и обязательная проверка предсказаний теперь входят
   в срок исполнения кандидата. Перед стартом процесса вычисляется оставшееся
   время; если оно исчерпано, процесс не запускается. Дополнительный абсолютный
   дедлайн не позволяет начать новый полный timeout после долгой подготовки.
4. Обратная связь содержит агрегированные ошибки внутренней проверки. Для
   регрессии это смещение, MAE и квантили абсолютной ошибки; для классификации
   показатели классов и основные путаницы. Метрики вычисляются по закреплённым
   байтам предсказаний, размер сводки ограничен 8 KiB. Outer/refit фазы этим
   интерфейсом не принимаются; индивидуальные строки и ID не передаются.
5. Добавлен `experiment_research_smoke.py` для короткой проверки настоящего Qwen
   на двух синтетических задачах. По умолчанию только preflight, без запросов.
   `--execute` разрешает последовательные запуски: до 4 запросов и до 600 секунд
   на задачу, общий потолок 8 запросов и 100k оценочных токенов. Стандартный
   бюджет времени 300 секунд на задачу. API/quota ошибка прекращает всю серию.
   Отчёт разделяет успешное внутреннее исследование с базовым результатом и
   полный путь сгенерированного кандидата через outer и публикацию. Записываются
   commit, dirty-признак и SHA-256 исполняемых исходников, без сборки архива.
6. Очистка известных исходных путей учитывает Windows long/8.3 aliases,
   смешанные компоненты, регистр и оба разделителя. Допустимые короткие имена
   запрашиваются у Windows, а не угадываются. При недоступности WinAPI сохраняется
   обработка известных буквальных путей; исходное написание пути до `resolve()`
   также учитывается. Единицы измерения и текстовые ограничения не удаляются.

## API и совместная работа

В этой рабочей среде отсутствуют `OPENAI_API_KEY` и `OPENAI_BASE_URL`, локального
`.env` нет. Preflight завершился с `missing_api_settings`, API requests: 0.
Реальный Qwen v3 и его конкурсное качество этим этапом не подтверждены. Для
запуска на настроенном компьютере:

```powershell
.venv\Scripts\python.exe experiment_research_smoke.py --execute --max-steps 4 --time-budget 300
```

На Linux: `.venv/bin/python` с теми же аргументами. Сводка и логи сохраняются
в `data/experiments/research_smoke/`, вне Git. Локальный общий счётчик двух задач
не является общекомандным суточным счётчиком. Остаток 600 ₽ неизвестен; оценочные
токены не приравниваются к usage провайдера или денежной стоимости.

На момент проверки GitHub новых PR с policy, portfolio и history adapter нет.
Зарезервированные модули коллег не изменялись и не заменялись другой реализацией.
Расширения остаются явно `not_connected`/`disabled`. Внутри конкурсного решения
по-прежнему один LLM-исследователь; дополнительные LLM-роли не подключались без
сравнения качества и стоимости.

## Практические пределы

Временные оценки являются ограниченной эвристикой с запасом, а не доказательством
сложности произвольного алгоритма. Жёсткое прерывание процесса через 3 часа
обеспечивает платформа. Представление разрешённых файлов не является OS-песочницей.
Передача смысла задачи улучшает вход исследователя, но поддержка ограничена
существующим CSV/метрическим контрактом; новый тип задачи автоматически не возникает.

Публичные и скрытые баллы не измерялись. Синтетические тесты проверяют протокол,
а не рост качества на конкурсных данных. Публикационный `delivery/solution.zip`
на этом этапе не пересобирается: он остаётся артефактом предыдущей версии
`0da9b95` с SHA-256 `8834e485010f6e07ad3723c6596701e12b8bd7d794f2968780d18cbecefc0c19`.
Тесты упаковки используют временные файлы; перед следующей отправкой потребуется
собрать архив текущего кода.
