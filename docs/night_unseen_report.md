## Независимый runner

`qualify_unseen_tasks.py` получает явный `--solver-root` и запускает выбранный
checkout только в дочернем процессе. Процесс аудитора не импортирует код
этого checkout. По умолчанию выполняется только preflight; запуск и re-audit
явные. Каждый план получает новый каталог, старый submission не допускается.

Генератор пишет в задачу только task.md и четыре CSV. Внешние ответы,
ожидаемый контракт и исходные хеши хранятся отдельно у аудитора. Путь к
ответам отсутствует в solver argv. Среда очищается по allowlist; конкурсные
API-настройки не передаются. Обычные процессы под тем же пользователем
сохраняют доступ к файловой системе: это граница потока данных, не OS sandbox.

План закрепляет исходный SHA, dirty flag, хеши исходников и входов, версии,
случаи, метрики, команды и конечные бюджеты. Проверка итогового CSV независимо
сверяет заголовок, literal IDs, порядок test, классы/вероятности и пересчитывает
метрику по внешним ответам. Status полноценной модели требует соответствующего
checkpoint/receipt и реальных артефактов полного refit. Target prior считается
отдельным допустимым fallback с неподтверждённым качеством.

Внешний timeout стенда — цензурированное наблюдение. Например, остановка
default solver через 90 s не доказывает нарушение платформенных трёх часов.
RSS/CPU обозначаются недоступными, если процессная среда не даёт их измерить.
Все обучения последовательны, до восьми потоков; для первой серии установлен
общий конечный лимит не более 3600 s с отдельными ограниченными перепроверками.

## Подтверждённые дефекты и минимальные воспроизведения

База проверяется теми же новыми regression-тестами из candidate checkout,
но импорты идут из отдельного неизменённого baseline worktree. Число failing
subtests не считается числом самостоятельных дефектов.

| ID | Воспроизведение в базе | Причина / исправление | Regression test |
| --- | --- | --- | --- |
| U01 | Лишнее CSV-поле становится индексом и сдвигает ID; короткая/пустая запись дополняется/пропускается | Перед pandas добавлена строгая проверка количества полей и CSV syntax | `test_night_data.StrictRecordTests` |
| U02 | Complex/date/timedelta/bool принимаются как числовые прогнозы; мнимая часть может исчезнуть | Общая проверка вещественных представлений до cast, используется также TaskSpec | `test_night_data` и `test_night_task_contract` |
| U03 | Настоящие `pd.NA`/`NaT` становятся строковыми классами | Реальные пропуски отклоняются; буквальные строки `NA`, `NaT`, `<NA>` сохраняются | `test_night_data` |
| U04 | Непустая пробельная категория/текст считается missing | Только пустая строка означает строковый пропуск | `test_night_data` |
| U05 | Полностью пустая категория downcast в float ломает строковый imputer | Поддерживается object dtype перед заполнением | `test_night_data` с настоящим pipeline fit |
| U06 | Буквальное `__MISSING__` сливается с generated imputer token | Инъективное экранирование токена и своего escape-пространства | `test_night_data` |
| U07 | `Metric: RMSE and mean absolute error` принимается как RMSE | Проверяются также полные алиасы вторых метрик; повтор того же алиаса в скобках допустим | `test_night_task_contract` |
| U08 | В class/positive declarations теряются `__`, `**`, backticks | Markdown-нормализация не меняет буквальные JSON/CSV payloads | `test_night_task_contract` |
| U09 | Generic target-named probability column ошибочно конфликтует с positive class | Сопоставление именного class-column отделено от generic target-column | `test_night_task_contract` |
| U10 | Multiclass AUC averaging берётся из постороннего примера; supplementary metric вызывает ложный отказ | Averaging читается только из ведущего предложения основной декларации | `test_night_task_contract` |
| U11 | Legacy validator принимает пустой test/submission и противоречивые dictionary/template/task | Для известных метрик используется TaskSpec, структурные проверки усилены | `test_night_validation` |
| U12 | Изменённый test без ID даёт `KeyError`, а пустой test может приниматься | Проверяются schema и непустые уникальные test IDs; возвращается invalid report | `test_night_validation` |

Публичные сигнатуры, TaskSpec keys и сериализация сохранены. Конвенция Macro F1
по отсутствующим классам не менялась: недостаточно основания объявлять её
ошибкой данного контракта. Отсутствующая/неподдержанная метрика сохраняет
legacy structural validator; такой путь не подтверждает качество ML.
