# Дополнительные кандидаты адаптивного исследования

`agent.research_extensions.run_research_extensions(state, assess, max_trials=6)` —
ограниченный host hook для режима `adaptive_search`. Native координатор вызывает
его после измерения стартового baseline, до обычных локальных рецептов. Без явного
`state.report["quality_options"]["adaptive_search"] == True` hook ничего не обучает.
Дополнительно нужны измеренный INNER baseline, доступное внутреннее разбиение,
поддерживаемая семантика задачи и открытая стадия исследования.

Это кандидаты, а не принудительная замена действующего решения. Каждый реальный
fit проходит существующий `assess` с замороженным исходником и рецептом. Выбор
использует только INNER metric; внешний контроль и полный refit остаются у v3.
Рост INNER не означает внешнего допуска или роста конкурсного скора.

## Очередь и пределы

Native маршрут передаёт `prioritize=True`. При совпадающей временной политике
INNER/outer регрессии сначала идут history → LightGBM → CatBoost → frequency;
для остальных задач — LightGBM → CatBoost → frequency → history. Затем следуют
ensemble и AutoGluon. Используются те же фабрики и шесть общих слотов, новые
модели или параметры обучения эта политика не добавляет. Прямой вызов helper
без `prioritize=True` сохраняет исторический порядок таблицы ниже.

Это даёт расширениям шанс до длинного warmup. Полного исполнения всех шести
кандидатов политика не обещает: каждый fit ограничивается оставшимся временем
и резервом финализации. После hook обычная очередь и adaptive продолжаются,
если их допускает заново рассчитанный резерв. Hook вызывается не более одного
раза. При раннем вызове ordinary finalist может отсутствовать, поэтому ensemble
штатно пропускается; суммарный эффект порядка проверяется native сравнением.

| Кандидат | Что проверяется | Когда пропускается |
| --- | --- | --- |
| Frequency | `log1p(count_fit(category))` добавляется к полному frozen baseline, включая все его компоненты | Нет категорий; больше 16 колонок; более 2 млн fit-row × selected-column visits |
| History | Одна схема из existing fit-feature discovery, strictly-past history blend с фиксированным весом 0.5 | История уже запрошена явно; не временная регрессия; inner/outer time policy различаются; discovery отказался |
| CatBoost early stop | Внутренняя fit-only проверка выбирает длину boosting, затем свежая модель обучается на всех fit строках | Разбиение внутри fit невозможно; лимит worker исчерпан |
| LightGBM early stop | Такой же протокол для второй семьи | Те же ограничения |
| Equal ensemble | Равное среднее 2–3 различных обычных компонентов baseline и ранее принятого INNER finalist | Нет принятого ordinary finalist; custom source; повтор уже измеренного ансамбля; слишком много компонентов |
| AutoGluon | Отдельный ограниченный CPU-кандидат из `agent.autogluon_candidate` | Пакет недоступен; research timeout меньше 60 секунд; внутренняя политика разбиения невозможна |

Фиксированный hard cap hook — **шесть вызовов assessor**, включая неудачные.
Factory/discovery без последующего fit не выдаётся за измеренный эксперимент.
Проверка резерва времени повторяется после подготовки кандидата. Если времени
не осталось, новая попытка не запускается. Спящий цикл и расходование всего
остатка ради самого таймера отсутствуют. Этот hook не отправляет API-запросы.

Frequency использует только объявленные категориальные признаки. Словари
обучаются существующим wrapper заново на `X_fit` каждого вызова; prediction
vocabulary, ID и target не используются. Existing worker limits в 4096 значений
на колонку сохраняются; словарь сверх лимита отклоняется перед fit baseline.

History использует существующий `discover_history_options`: отдельному worker
передаются только feature columns разрешённых INNER-fit строк. Частичные/limited
предложения не активируются. Source/recipe создаются существующими history
factories. Наличие ручного `history_config`, явного `history_auto` либо уже
запрошенного history report предотвращает второй одинаковый поиск.

Два early-stopping кандидата используют модуль `agent.boosting_candidate`.
Настройки соответствующей семьи берутся из принятого ordinary finalist, затем
из baseline; при отсутствии подходящей ordinary семьи используется обычный
ограниченный default `make_model_config`. Произвольные поля LLM-рецептов не
копируются. Верхний предел — 2000 итераций, patience 50, а validation policy —
копия явного `gate.choice`. Дополнительная проверка делается только внутри
`X_fit/y_fit`, после чего выбранная длина используется свежим refit на всех
переданных fit строках. Внешние labels не передаются early stopping.

Ensemble берёт `state.selected_candidate`, захваченный до extension round: это
уже принятый, измеренный кандидат, а не запись, добавленная перед неудачным fit.
Baseline и finalist должны содержать **ровно текст `BASELINE_SOURCE`**; произвольный
LLM Python не смешивается с host pipeline. Model configs и feature configs
перепроверяются, компоненты дедуплицируются по эффективной конфигурации.
Веса не подгоняются по outer, порядок классов обслуживает existing baseline.
Компоненты происходят из измеренных рецептов; отдельная независимая метрика
каждого компонента здесь не заявляется. Это не stacking и не OOF калибровка.

AutoGluon получает копию `gate.choice`, лимит 8 CPU, 0 GPU в backend и мягкий
memory budget 24 GB. Его recipe time limit — от 30 до 180 секунд, не больше
четверти текущего research timeout. Соблюдение deadline и ресурсов требует
существующего host worker; эти аргументы библиотеки не являются OS sandbox.

## Сбои и отчёт

До и после каждой фабрики/попытки проверяются host source, входные данные и
неизменность frozen recovery baseline. Эти проверки повторяются **вне** блока
обработки optional modelling failures. Изменение baseline object, его файлов,
исходников проекта или входных данных завершает исследование ошибкой. Проверка
attempted frozen candidate также находится вне optional catch. Допустимый
accepted candidate может меняться обычным assessor; его frozen files проверяются.

Обычная ошибка модели или отсутствие optional зависимости фиксируются и
позволяют перейти к следующему кандидату. Свободный текст исключений не входит
в report: сохраняются ограниченные причины и известная категория ошибки.
`refit_budget` сохраняется как причина недопуска и не переименовывается в
плохое качество. Публикацией CSV hook не занимается и существующий CSV не читает
и не заменяет.

`run.json.research_extensions` содержит версию, scope, предел, actual attempts,
verified/accepted counts, `schedule`, `order` и запись каждого типа, включая skip reason. History
дополнительно имеет `history_research.policy = adaptive_auto_v1`, actual attempt,
frozen hashes и feedback. Discovery и measurement остаются разными событиями.

## Проверка

```bash
python -m unittest tests.test_research_extensions -q
```

32 fake-host tests проверяют caps, reserve после подготовки, целый baseline,
отсутствие held vocabulary access, пропуск повторной истории, несовместимых
источников ансамбля, package/budget skip и обязательное распространение
integrity ошибок после неудачного optional fit. Модели в этой серии не обучаются,
API и сеть не используются. Настоящие paired measurements и качество этих
кандидатов должны оцениваться отдельными native прогонами перед заявлениями о
пользе. Сам по себе этот отчёт роста качества не подтверждает.
