## Контекст и цель

Репозиторий: https://github.com/NolReaction/alfa-automl-agent.
На платформе агент запускается как `python3 solution.py task.md`, самостоятельно
обучается и сохраняет `submission.csv`. На задачу доступны 8 CPU, 32 ГБ RAM,
3 часа; внутренний потолок агента 10500 секунд. Используются разрешённые
библиотеки из репозитория, модели обучаются с нуля. Собственные внешние API,
данные и предобученные модели в решение не добавлять.

Главная цель твоего блока: проверить, помогает ли калибровка решения для
Macro F1, если получить больше корректных calibration-предсказаний внутри
разрешённого train. Только классы меняются правилом
`argmax(probabilities * multipliers)`. Вероятности для LogLoss/AUC не менять.

Уже существуют `agent/classification_decision.py`, обычное и guarded-правило,
его тесты и эксперименты. Повторно их реализовывать не надо. В публичном
TRAIN текущий inner selection содержал всего 8 примеров одного редкого класса.
Guard требует минимум 5 примеров каждого класса в tuning и 5 в selection;
поэтому прежняя маленькая calibration-часть неизбежно возвращает identity.
Нельзя исправлять это снижением порогов после просмотра результатов.

Research v3 изолирует outer-fit представление, фиксирует рецепт до outer и
сам выполняет refit/публикацию. Его нынешний Macro-F1 callback возвращает метки,
а не обязательные сырые вероятности. Твой модуль и экспериментальный callback
нужно сделать отдельно; готовую интеграцию с v3 этим не объявлять.

## Зафиксированный протокол без утечки selection

Используй одну небольшую конфигурацию базовой модели, установленную заранее.
Весь подбор конфигурации и preprocessing должен исключать B, outer и test.

1. Host отделяет внешний audit. Модулю передаётся только разрешённый outer-fit.
2. До обучения host делит outer-fit на A (tuning) и B (selection), примерно
   70/30, сохраняя исходные группы дублей целиком. Индексы фиксируются.
3. Три OOF-fold строятся только внутри A. Каждая строка A получает ровно одно
   предсказание модели, которая не видела её ответ и её группу.
4. Отдельная модель обучается на всём A и предсказывает B. Ответы B не участвуют
   ни в одном fit, preprocessing, выборе конфигурации или tuning кандидата.
5. Передай объединённые вероятности `[OOF_A, predictions_B]` и ответы `[y_A, y_B]`
   в существующий `fit_guarded_decision_rule`, с явными tuning/selection indices.
   Существующие defaults оставить без изменения. Процедура сначала выбирает
   одного кандидата на A, затем B может только допустить его или identity.
6. Заморозь JSON-правило и настройки. После этого модель обучается на A+B,
   предсказывает outer. Правило больше не обучается.
7. Отдельно проверь перенос того же правила после полного production-refit.
   Это проверяемая гипотеза: распределение вероятностей после refit меняется.

Обычный OOF на всём outer-fit с последующим разрезанием вероятностей на A/B
не даёт независимого selection-допуска: ответы B попали бы в модели,
сформировавшие tuning-вероятности. Такой протокол не использовать.

Scope v1: IID и групповая классификация с явной политикой host. Временные
задачи возвращают явный unsupported/identity; не подменяй chronology случайным
OOF. Не меняй seed/split из-за плохой поддержки класса после начала оценки.

## Интерфейс модуля

Согласованные публичные имена:

```python
def fit_oof_guarded_rule(
    X_allowed, y_allowed, classes, *, groups, split_policy,
    tuning_rows, selection_rows, folds, fit_predict,
    fold_timeout_seconds, deadline, clock, guard_options=None,
):
    ...
```

Все индексы локальны относительно `X_allowed/y_allowed`. A/B уникальны,
не пересекаются и покрывают разрешённые строки; их группы не пересекаются.
`folds` содержит ровно три словаря `fit_rows`, `held_rows`, с индексами только A.
Fit и held каждого fold разделены по группам; held части покрывают A ровно раз.
Каждый fit содержит все точные объявленные классы. Структурно неверный индекс,
пересечение групп или выход за A является ошибкой контракта, а не успешным fit.

Callback получает только соответствующие подвыборки:

```python
fit_predict(
    X_fit, y_fit, X_predict, *, timeout_seconds, fit_index,
)
# -> {"probabilities": matrix, "classes": exact_column_labels}
```

Каждый вызов заново обучает preprocessing и модель только на X_fit/y_fit.
Метки X_predict callback не получает. Он возвращает конечную матрицу [0,1],
с суммой строки 1 и всеми классами; порядок колонок выравнивается явно.
Не преобразовывать буквальные метки `01`, `NA`, `class c` в числа/пропуски.
В experimental host реальный fit выполняется ограниченным дочерним процессом
через существующий механизм исполнения. Передача timeout обычной функции
сама по себе не гарантирует остановки процесса.

Модуль не читает файлы/окружение, не строит свои разбиения, не выполняет сеть.
Часы и конечный deadline передаёт host после вычитания финального резерва.
Перед каждым fit вычисляется `min(fold_timeout_seconds, deadline - clock())`;
проверяется срок и после возврата. Время всех четырёх callback входит в один
исходный бюджет. Незавершённый OOF не используется для обучения правила.
Timeout, модельный сбой, недостаток времени/поддержки дают identity с причиной;
неверная структура/вероятности дают контролируемую ошибку контракта.

Результат: конечный JSON-совместимый wrapper с version/status/reason/classes,
выбранным rule/candidate_rule, guarded diagnostics, поддержкой классов,
числом завершённых fit, фактическими временами и хешами разбиений/правила.
OOF-матрицы допускаются отдельным диагностическим результатом, не огромным JSON
в recipe. Модуль делает 3 OOF fit + 1 A→B fit. Последующий A+B→outer fit делает
host: всего 5 fit против одного у identity, то есть 4 дополнительных.
Production-refit после outer учитывается отдельно в обоих плечах.
