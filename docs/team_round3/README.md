# Следующий этап: история и Macro F1

Дата: 21 октября 2026. Координация: Дима.

## Состояние и цель

Организаторы подтвердили две разные причины прежних слабых результатов:
одна отправка не сохранила итоговые предсказания после ошибки, другая отработала,
но не превзошла baseline на одной задаче. Сам по себе score не доказывает отказ
Qwen или недостаток вычислительной мощности.

PR #15 и #17 уже находятся в main: строгие контракты, сохранение проверенного
результата, локальное продолжение после остановки API-диалога, исходный deadline.
Экспериментальный strong_v1 не прошёл допуск в defaults: обе публичные TRAIN
пары при 300 s ухудшились, classification при 900 s также проиграла legacy.
Эти результаты не являются оценкой платформы.

PR #16 принимается как библиотека истории и экспериментальный адаптер.
Дополнительно исправлена context-зависимая потеря точности period_json;
96 профильных history tests прошли. Принятие модуля не означает его
автоматическое включение в поиск или подтверждение выигрыша нынешнего AutoML.
Фактический статус полного CI/merge нужно смотреть в самом PR.

## Наша следующая работа

1. Принять #16 после проверки совместного дерева с актуальным main на двух ОС.
2. Добавить отдельный явный history recipe: сырой X, прошлое только из fit,
   config/вес в замороженном JSON, baseline без истории всегда доступен.
3. Начать с explicit config и фиксированного веса; подключать schema-proposer
   после отдельной приёмки. Универсальный код не содержит публичных имён колонок.
4. Сравнивать конфигурации и веса на INNER в одном исходном бюджете. После
   фиксации рецепта outer не возвращается исследовательскому диалогу.
5. Проверить временные разбиения, полное обучение, корректный CSV и восстановление
   после сбоя кандидата. Неудачный refit сохраняет уже допущенный baseline.
6. Выполнить парное сравнение нынешнего поиска с поиском + history при равном
   времени, затем отдельную замороженную synthetic confirmation. Public TRAIN
   остаётся известной sanity-проверкой, не скрытой независимой оценкой.

Это план следующей реализации, а не список уже добавленных возможностей.
Включение по умолчанию допускается только после результата измерений.

## Общая дисциплина

Все работают в отдельных worktree от одной зафиксированной базы после #16,
записывают её SHA до экспериментов и не обновляют её посреди серии.
Сохраняются история коммитов и отрицательные результаты. Свои ветки можно
пушить и открывать PR; итоговый merge, ZIP и платформенные отправки у Димы.

Не делаем внешних API-запросов для этих исследований; ключи и .env не нужны.
Дочерние fits, подбор, calibration, refit и prediction входят в общий бюджет.
Не запускаем тяжёлые серии одновременно на одном компьютере. Указанный лимит
RAM не равен измеренному RSS; ограничение среды указывается честно.

Полезный результат задания: воспроизводимый ограниченный модуль, проверенный
контракт и честное решение о пользе, включая отказ от гипотезы. Число моделей,
число агентов и продолжительность сами по себе не являются улучшением качества.
