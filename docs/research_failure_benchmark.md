# Полный агент при отказе API

Этот этап проверяет настоящий маршрут Research v3: подготовку задачи,
стартовый AutoML, отказ API, локальное продолжение, внешнюю проверку,
полное обучение и публикацию `submission.csv`. Подменяется только API-клиент.
Модели, очередь рецептов, разбиения и бюджет остаются производственными.

## Контроль на Windows

Пользователь получил следующие CLI-результаты на одном синтетическом
`nonlinear_regression`, seed 42, с бюджетом 90 секунд на запуск:

| Настройка | Audit MAE | Время |
| --- | ---: | ---: |
| Только стартовая модель | 7.558306618474695 | 3.391 s |
| AutoML без новых рецептов | 6.441069312691177 | 39.469 s |
| AutoML с `--metric-recipes` | 2.886815603816453 | 51.250 s |

Относительно AutoML без новых рецептов ошибка ниже примерно на 55.18%.
Это наблюдение на одной синтетической задаче и одном компьютере, не конкурсный
score. Разница с Linux-пилотом сама по себе не доказывает ошибку: поиск
ограничен измеренным временем, поэтому состав завершённых кандидатов может
различаться. Для точного объяснения конкретной пары нужны полные отчёты.

## Что доказывает имитация отказа

```powershell
.venv\Scripts\python.exe benchmark_agent.py --cases nonlinear_regression imbalanced_binary --seeds 42 --modes research_api_failure --time-budget 180
```

Новый режим включается явно и не делает настоящих сетевых запросов.
Имитированный вызов учитывается отдельно от внешних API-вызовов.
Успешная проверка должна подтвердить версию протокола 3, причину
`api_error`, статус агента `fallback`, единственную попытку клиента,
отсутствие ответов и успешных LLM-экспериментов, а также новую проверенную
публикацию после финального обучения. Отчёт связывается с конкретным
каталогом запуска, а не с найденным по шаблону старым `run.json`.

Нулевое число локальных обучений не объявляется проверенным локальным
продолжением. Оно может быть честным следствием резерва времени или уже
исчерпанной очереди; такой запуск сохраняет диагностическую ценность.
Конкретные причины пропуска и счётчики должны оставаться в отчёте.

Имитированный немедленный отказ не проверяет реальную длительность сетевого
таймаута, повторы SDK, доступность сервиса или качество гипотез Qwen.
Ответы независимого audit по-прежнему находятся вне входов решателя.
Разделение файлов не является OS-песочницей.

## Дополнительные MAE-семейства

Дополнительные семейства задаются до получения оценок. Они проверяют цель
со знаками обоих типов, линейную зависимость с симметричным шумом и отдельный
механизм тяжёлых выбросов. Старые шесть семейств и их генерация сохраняются;
новые выбираются явно, чтобы прежние команды не стали неожиданно длиннее.

```powershell
.venv\Scripts\python.exe benchmark_agent.py --cases mae_signed_nonlinear mae_symmetric_linear mae_heavy_tailed --full --modes automl --time-budget 90 --output data\experiments\agent_benchmark\mae_control
.venv\Scripts\python.exe benchmark_agent.py --cases mae_signed_nonlinear mae_symmetric_linear mae_heavy_tailed --full --modes automl --time-budget 90 --metric-recipes --output data\experiments\agent_benchmark\mae_metric --compare-report data\experiments\agent_benchmark\mae_control\report.json
```

Каждая серия содержит девять запусков с бюджетом до 90 секунд каждый.
Дополнительные случаи не меняют результаты уже проведённых пилотов.
Полные отчёты сохраняются под `data/experiments/agent_benchmark/`, а сводка
этого этапа и результаты Linux/Windows CI публикуются в
[PR #11](https://github.com/NolReaction/alfa-automl-agent/pull/11).

Настройки качества пока остаются включаемыми опциями. Полученный выигрыш
не означает, что `--metric-recipes` уже включён в конкурсном запуске без
аргументов, и не подтверждает универсальную пользу `log1p`.
