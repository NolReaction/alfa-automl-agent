# Конкурсный запуск

Сверено 20 октября 2026 с файлами, скачанными из формы отправки:
`baseline.py`, `requirements.txt`, «Альфа Хак_AutoML.pdf». Исходники организаторов
не включаются в наш ZIP. Эта инструкция описывает проверенные требования и
реализацию; она не заменяет оригинальный кейс.

## Интерфейс

```bash
python solution.py /path/to/task.md
```

Без позиционного аргумента читается `task.md` из текущего каталога.
Относительные пути данных считаются от каталога Markdown. Для обеих публичных
задач итог — `submission.csv` рядом с Markdown, в порядке ID из `test.csv`.
Каждая задача запускается отдельно; результаты между задачами не передаются.

`solution.py` находится в корне ZIP; модули `agent/` лежат в том же архиве.
MCP в официальном baseline — внутренняя реализация инструмента Python,
а не отдельный обязательный интерфейс запуска нашего архива.

| Режим | Поведение |
| --- | --- |
| `--mode auto` (по умолчанию) | Использует LLM, если в окружении заданы все три переменные API; без них явно включает offline fallback |
| `--mode offline` | Четыре фиксированных ML-рецепта, без чтения ключей и без API-вызовов |
| `--mode llm` | Исследование с LLM; можно загрузить настройки из локального `.env` |

Переменные из baseline: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`.
`auto` читает только окружение процесса: `.env` разработчика не должен незаметно
переключать конкурсный запуск. Частично заполненное окружение вызывает понятную
ошибку с названиями недостающих переменных, без значений ключей.
Модель и адрес берутся из настроек организаторов; сторонние ключи не подставляются.

## Что требует кейс

Страницы 5, 13–14 и 17 описывают систему под управлением LLM: анализ задачи,
генерацию и запуск кода, проверку гипотез, сравнение по своей валидации и выбор
следующего эксперимента. Четыре заранее заданных рецепта сами по себе этого
не обеспечивают. Offline fallback сохраняет полезный ответ при отсутствии API,
но не является подтверждением полного выполнения требований к агенту.

Кейс указывает общий API-бюджет команды на время разработки — 600 рублей в день.
Он не описывает отдельно лимит API во время проверки. Фактическую выдачу
`OPENAI_*` контейнеру и работу Qwen ещё нужно подтвердить реальной отправкой;
локальная имитация API проверяет протокол, а не доступность сервиса.

## Среда и ограничения

- Python 3.12; 8 CPU; 32 GB RAM; максимум 3 часа на задачу.
- Только данные задачи; без загрузки внешних данных и предобученных моделей.
- Используемые 11 пакетов и их версии входят в официальный список. Наш
  `requirements.txt` — нужное подмножество; при запуске пакеты не устанавливаются.
- Внешний интернет из контейнера запрещён. В коде обучения нет сетевых загрузок.
- ZIP до 128 МБ; 3 отправки на команду в день, обновление в 00:00 МСК.
- Внутренний лимит исследования — 10 500 секунд, включая стартовое обучение;
  offline по умолчанию получает 600 секунд. Модели и вычислительные потоки
  ограничены восемью.

## Проверка и баллы

Для RMSE/Macro F1 исследовательский цикл сначала закрепляет holdout и проверяет
автономную стартовую модель. Сгенерированный код работает на копии входов и
пишет `research_hypothesis.json`, `holdout_predictions.csv`, `submission.csv`.
Управляющий процесс пересчитывает качество на исходных закреплённых ID/ответах;
публикация происходит только при строгом улучшении. Старые артефакты удаляются
перед следующим вызовом инструмента, поэтому печать текста не считается
измеренным экспериментом. Принятые CSV/holdout хранятся отдельно от рабочей папки.
Это проверка результатов, не изоляция произвольного кода и не доказательство
отсутствия утечки в его обучении.

Public проверяет две известные задачи на скрытых целевых значениях. Локальные
RMSE/Macro F1 не являются баллами платформы. Согласно приложению 3, каждая
метрика переводится в баллы относительно результата бейзлайна платформы;
результат на уровне бейзлайна или хуже даёт ноль. Значения этого бейзлайна нам
не известны, поэтому предсказать public score из локальных метрик нельзя.

Private заново запускает решение на двух неизвестных задачах; их метрики не
раскрыты. Текущая независимая проверка качества поддерживает CSV-контракт,
RMSE и Macro F1. На иных метриках исследовательский путь требует отдельной
проверки; успешный public не доказывает универсальность решения.

Перед отправкой: `dev_check.py`, проверки приложения, сборка `build_submission.py`,
запуск извлечённого ZIP вне репозитория. Затем капитан проверяет CI и сливает PR;
архив собирается именно из принятой версии. Ключи, данные, модели, панель,
тесты и результаты экспериментов в архив не входят.
