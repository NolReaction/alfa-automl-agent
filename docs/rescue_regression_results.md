## Решение

Передать изолированного CatBoost-кандидата для проверки в общем host. Он улучшает
два из трёх заранее объявленных временных TRAIN-срезов, но ухудшает самый ранний.
**Автоматическая замена действующего пути не рекомендована.** Нужны native
900s on/off на одном integration SHA, проверка ресурсов на наблюдаемой машине и
отдельный system A/B. В этой ветке общий router, планировщик и default activation
не менялись. Улучшение на платформе не измерено.

## Что реализовано

`agent/regression_base.py`: CatBoost/LightGBM на исходной шкале RMSE, максимум
2000 итераций, patience 100, один последний fit-период для ранней остановки,
затем свежий refit на всех разрешённых fit-строках. Для одного периода —
фиксированные 400 деревьев. Вся обработка признаков обучается внутри fit;
порядок fit нормализуется по содержимому объявленных признаков и fit-target.
CPU, 8 потоков, без API и установки пакетов в runtime.

`agent/regression_history.py`: строго прошлые mean/last/decay, счётчик наблюдений,
давность, неоднозначность. Decay = 0.5 за единицу числового периода. Политика
`past_unique_only` исключает ключ, который дублировался в любом доступном прошлом
периоде. Нет ключа/прошлого/валидного периода — прогноз базы сохраняется точно.
Калибровка выбирает из 19 фиксированных вариантов только по внутренним fit
предсказаниям той же ранней модели; новых fits для выбора истории нет.
Нужно минимум 64 применимых calibration-строки, иначе фиксированный mean 0.5.

`agent/regression_candidate.py`: композиция базы и истории с обычным контрактом
`fit_predict(...) -> {"predictions": ...}`. Сохраняет неоценочные sidecar-отчёт
и три абляции от одного и того же полного refit.

`agent/regression_discovery.py`: opt-in полный поиск top-one с лимитами 12M
планируемых cell-visits, максимум 192 допустимых проверок, 12 столбцов, ширина 3,
8 секунд и sampled 1 GiB. Число проверок уменьшается по числу строк. Partial/
limited никогда не активируются. Старые default 8M/48 и форма их ответа сохранены.
Схему находят один раз на host INNER-fit features и фиксируют для дальнейших фаз.

## Разделение сравнения

Срезы для разработки: годы 2, 3, 4, fit всегда строго раньше прогнозируемого
года. Они объявлены до нового обучения в `rescue_regression_plan.md`.
Годы 3/4 также использовались прежними исследованиями. Это не blind test.
Известный год 5 проверяется только после фиксации CatBoost и алгоритма.
Конкурсные TEST-ответы отсутствуют и не восстанавливались.

Native main получил лимит 900s; изолированный кандидат — 360s. Это скрининг
готового CSV, **не equal-scheduler native A/B**. Более того, direct candidate
имеет один внутренний temporal split, а main дополнительно делит данные на
outer/INNER. Объём доступных discovery-признаков поэтому различается. Этот
эффект нельзя приписать только качеству модели.

| Предсказываемый год | main native | Cat base | Cat mean 0.5 | Cat calibrated | LightGBM calibrated |
| --- | ---: | ---: | ---: | ---: | ---: |
| 2 | 47.854135 | 49.752709 | 49.752709 | 49.752709 | 52.352502 |
| 3 | 72.631990 | 55.794171 | 55.794171 | 55.794171 | 55.812422 |
| 4 | 47.303062 | 46.824893 | 43.386325 | 42.895056 | 42.176444 |

CatBoost выбран до года 5 из-за меньшего ухудшения на раннем срезе; LightGBM
немного лучше на четвёртом. В разработке победил mean с весом 0.75, без
shrinkage. Польза last/decay/shrinkage отдельно пока не установлена.

## Ошибки и оставшаяся работа

На годе 4 история применяется к 1342 строкам (10.37%). Для CatBoost она снимает
4.565M SSE относительно той же базы; 67.56% этого выигрыша приходится на 113
строк выше fit-p99. После улучшения этот хвост всё ещё даёт 48.54% SSE.
Без применимой истории остаётся 89.63% строк и 91.29% остаточного SSE.

На годе 2 CatBoost добавляет 1.679M SSE (+8.09%). Диапазон target p50–p90 даёт
80.70% добавленной ошибки; 104 строки с 6+ пропусками — 31.87%. Новые категории
объясняют лишь 0.21%; верхний хвост даже улучшается. Доля Residential меняется
с 6.85% fit до 71.20% held, и этот сегмент даёт 65.24% добавленной SSE. Это
описательные разрезы, не доказательство причинности; пересекающиеся доли нельзя
складывать. На годе 3 выигрыш смешан с обходом слабого seed-only fallback main.

Новый ключ на fit годах 1–2: State_Factor + facility_type + year_built, 153
проверки; на fit 1–3: floor_area + year_built, 37 проверок. Это зафиксированные
результаты feature-only discovery, а не runtime-условия по названиям. Для раннего
ключа 78.73% строк года 4 неоднозначны и исключены. Расширение покрытия само по
себе не является критерием принятия.

## Действующий native маршрут

Discovery получает только INNER-fit признаки. Затем кандидат измеряется на
INNER, фиксируется, сравнивается с baseline на outer и лишь после этого
выполняется full refit. Outer используется для принятия и не является
независимой несмещённой оценкой. History wrapper оборачивает frozen recovery
baseline, а не лучший позднее найденный boosting finalist.

На годе 2 main публикует равный blend CatBoost500-depth8 + ExtraTrees250-leaf4;
его host split random, история не допускается. На годе 3 outer-fit содержит
только год 1, INNER недоступен: main публикует Ridge(alpha=1) за 7.615s. На годе
4 baseline — Ridge(alpha=1), итог — равный Ridge + ExtraTrees200-leaf1 с половиной
признаков. Discovery там видит только 2117 строк одного года и отказывается за
0.484s. Ни один из этих трёх native запусков не исполняет history-кандидата.

Measured baseline search / baseline INNER / refit child seconds:
год 2 30.063 / 2.928 / 3.053;
год 3 отсутствует / отсутствует / 1.621;
год 4 3.762 / 1.475 / baseline 2.241 + candidate 4.849.
INNER включает host preparation/checking; search/refit — child execution.

## Контракт подключения

Eligible: regression RMSE, объявленный числовой period, согласованная temporal
валидация, разрешённые host fit-строки, достаточный остаток бюджета для INNER,
outer и refit. Предпочтительна возможность внутренней temporal-калибровки;
одно-периодный fallback реализован, но его автоматическое продвижение не
рекомендовано по измерениям года 2. Host сохраняет обычный baseline при skip,
ошибке, timeout или отсутствии подтверждённого улучшения.

```python
from agent.regression_candidate import candidate_source, make_regression_recipe

recipe = make_regression_recipe(
    gate.choice["time_column"], engine="catboost",
    history_config=frozen_history_config,  # None or feature-only host discovery
)
source_text = candidate_source()
# Existing host: freeze_candidate(source_path, recipe, destination),
# then the ordinary _assess_candidate / finalization lifecycle.
```

Для opt-in поиска вызвать `discover_regression_schema_bounded` один раз с
точным host INNER-fit feature-frame; передать `selected_config` либо None.
Не передавать ID/target/INNER-held/outer-held/TEST и не запускать discovery
повторно на полном TRAIN. Код не принимает решения по имени задачи/пути/ID.
Сам factory не меняет router. При отсутствии схемы выполняется база; некорректный
контракт отклоняется. Recipe содержит фиксированные ограничения и алгоритм;
итерации/вес могут заново выбираться исключительно внутри fit каждой фазы.

Для честного измерения капитан должен вернуть integration SHA и переключатель
кандидата. Обе arms native900s должны использовать этот SHA и различаться
только включением кандидата. Сравнение d055728 с итоговой системой вести отдельно.
До появления этого контракта корректной команды нового native флага не существует.

## Проверки и границы доказательства

77 focused rescue tests и 145 существующих history tests прошли. Тесты покрывают
строго прошлые метки, будущие/одновременные периоды, дубли, перестановки, точные
numeric keys, отсутствие мутаций, fit-only preprocessing/calibration, fallback,
лимиты discovery и исходный default. Проверены callback-путь до реальных
CatBoost/LightGBM через изолированные измерения.

Сохранённые CSV независимо пересчитаны: точный ID/order, конечные значения,
source/recipe/receipt/output hashes и число refit-строк. На первых 18 абляциях
разница независимого RMSE ≤7.1e-15. Peak RSS, process-tree CPU и cleanup здесь
недоступны: **unknown**, не ноль. Конфигурированный лимит 32 GiB не доказывает
его соблюдение. Успех процесса и валидный CSV не заменяют ресурсовую квалификацию.

Модельный стек совпадает с официальными версиями Python3.12, numpy1.26.4,
scipy1.12.0, pandas2.2.3, sklearn1.5.2, CatBoost1.2.8, LightGBM4.6.0,
joblib1.4.2, threadpoolctl3.6.0. Это необходимый subset, не образ всей платформы:
необязательные AutoGluon/Torch не установлены; PyYAML/matplotlib transitive версии
отличаются и не используются новым кандидатом для обучения. Полный package
inventory сохранён в evidence. Это дополнительная граница system-сравнения.
Публичные тяжёлые fits запускались последовательно; ранние скрининги частично
совпали с synthetic/spy unit checks. Wall timings описывают эти запуски, а не
контролируемый benchmark скорости.


## Известный год 5 и полный TRAIN refit

На **исходной полной задаче** main действительно выбрал history wrapper:

| На одних и тех же 35,000 fit / 18,308 held строках года 5 | RMSE |
| --- | ---: |
| Native frozen baseline: равный LightGBM100 + ExtraTrees300 | 49.021324 |
| Native принятая история: fixed mean, вес 0.5 | 44.569657 |
| Изолированный CatBoost, без истории | 44.609419 |
| Тот же CatBoost + fixed mean 0.5 | 39.475939 |
| Тот же CatBoost + fit-only calibrated history | 39.471458 |

Ближайшее сравнение с **работающей** историей main: **−11.44% RMSE**.
Состав, значения признаков и порядок исходных fit/held строк независимо сверены;
RMSE пересчитан по сохранённым CSV. Native выбирает кандидата на этом outer,
поэтому это известный development-срез, а не независимый тест. Бюджеты и
процедуры исполнения различаются; same-scheduler on/off всё ещё не выполнен.

Исходный native занял 513.014s из cap900s. Baseline search 81.509s; discovery
2.786s на 22,054 INNER-fit строках, 37 проверок, найден floor_area + year_built.
Baseline/history INNER host calls 7.318/8.104s; full refit child 17.704/17.123s.
Принятый wrapper и полный CSV подтверждены receipts и хешами. Полный аудит:
`results/native_original_audit.json` в архиве и соответствующий раздел JSON.

Отдельный запуск **производной задачи** с укороченным TRAIN дал native main RMSE **47.591119**, Cat base **44.609419**,
Cat mean0.5 **39.475939**, Cat calibrated **39.471458**. Это известная проверка
совместимости, не blind и не платформенный score. Native main здесь публикует
равный ExtraTrees200/leaf1/max_features0.5 + CatBoost100/depth6; discovery видит
11,175 строк, исчерпывает 48 проверок за 1.738s и history не исполняет.
Native baseline search 46.810s, baseline INNER 3.468s, refit 8.219s; общий wall 321.162s.

Cat выбирает 570 деревьев и last/.75 без shrinkage только по внутреннему году4;
host wall 13.978s из cap360s, ES 4.575s, свежий refit 4.435s. Улучшение относительно
этого производного main 17.06% RMSE; это не выигрыш относительно активной истории
исходной задачи. Схемы вложенности/планировщики различаются. Last-калибровка
почти равна fixed mean (.00448 RMSE), поэтому универсальный выигрыш last/decay
не установлен. Без истории 31.09% строк дают 75.27% остаточной SSE; новые категории
17.43% строк дают 45.52%. Разрезы пересекаются.

Полный TRAIN: **53,308→22,449**, wall 28.540s из cap360s, ES 10.867s, свежий
refit 10.899s. Выбраны 1146 деревьев и decay/.75/shrinkage1. Это заново измеренные
параметры внутри разрешённого fit, по неизменному заранее зафиксированному
алгоритму. В полном fit год 5 уже TRAIN: его внутренняя калибровка не является
дополнительной независимой оценкой. TEST качество неизвестно; coverage 76.05%
не является качеством. Source/recipe bytes и SHA256 совпадают с известным годом5;
полный состав/порядок fit/predict, nonce и publication receipt независимо сверены.
