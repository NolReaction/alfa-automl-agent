# Ошибки классификации и проверка весов классов

Разбор выполнен на публичной задаче сетевых атак, Python 3.12 и зависимостях из `requirements.txt`. Проверка по группам одинаковых исходных признаков, seed 42: 70 155 строк обучения и 17 515 проверочных строк, пересечение групп — 0. Это один локальный holdout, не оценка скрытого test.

## Что показывает исходная модель

RandomForest с `class_weight="balanced_subsample"` даёт Macro F1 **0.593601384456833**, accuracy **0.776820**. Accuracy не заменяет основную метрику: Macro F1 даёт каждому классу одинаковый вес.

| Класс | F1 | Precision | Recall | Истинных строк | Предсказаний |
| --- | --- | --- | --- | --- | --- |
| Backdoor | 0.131528 | 0.080760 | 0.354167 | 192 | 842 |
| Analysis | 0.169249 | 0.109737 | 0.369792 | 192 | 647 |
| DoS | 0.395726 | 0.357523 | 0.443069 | 1 212 | 1 502 |
| Worms | 0.571429 | 0.666667 | 0.500000 | 16 | 12 |

Проблема Backdoor/Analysis включает много ложных срабатываний: прогнозов этих классов намного больше, чем истинных примеров. Поэтому усиление весов редких классов не обязательно улучшает Macro F1.

Частые ошибки исходного RandomForest:

| Истинный класс → прогноз | Строк | Доля истинного класса |
| --- | --- | --- |
| Normal → Fuzzers | 813 | 14.35% |
| Exploits → DoS | 618 | 18.75% |
| Exploits → Backdoor | 344 | 10.44% |
| DoS → Backdoor | 286 | 23.60% |
| Exploits → Analysis | 262 | 7.95% |

Матрица и метрики классов теперь сохраняются в отчётах классификации и показываются в Alfa Lab. Для старых локальных запусков они восстанавливаются из сохранившихся проверочных предсказаний после проверки связи с данными, ID, правильными ответами и общей метрикой.

## Пять заранее заданных вариантов

Исследовательский скрипт меняет только `class_weight`, остальные настройки внутри каждого семейства одинаковы. Он обучает модели на обучающей части и сохраняет проверочные предсказания; переобучения на всём train и записи `submission.csv` нет.

```powershell
.\.venv\Scripts\python.exe experiment_classification_weights.py data/classification/task.md
```

По умолчанию создаётся новая папка в `delivery/classification-experiments/`. Можно указать другую **новую** папку через `--output-dir`. Папка задачи и существующие каталоги вывода не перезаписываются. Скрипт сохраняет снимок входов, их SHA-256, схему проверки, точные настройки, метрики и CSV с проверочными предсказаниями. Вызовов API нет.

| Вариант | Macro F1 |
| --- | --- |
| RandomForest `balanced_subsample`, контроль | 0.5936013845 |
| ExtraTrees `balanced`, контроль | 0.5889124833 |
| RandomForest без весов | 0.5582763142 |
| RandomForest `balanced` | **0.6009466538** |
| ExtraTrees без весов | 0.5526283825 |

Контрольный RandomForest воспроизвёл прежние ID, правильные ответы и предсказания. Все метрики независимо пересчитаны по CSV, исходные файлы не изменились.

У `balanced` прирост над контрольным RF — **0.007345**. Около 67% этого прироста приходится на изменение F1 Worms: правильно найдены 9 из 16 строк вместо 8. Улучшение Analysis даёт ещё около 0.001709 Macro F1, а F1 Backdoor немного снижается. Это предварительный результат, чувствительный к малой проверочной выборке редкого класса.

Снятие весов целиком ухудшило оба семейства моделей. Одного наблюдения о чрезмерных прогнозах редких классов оказалось недостаточно для такого изменения.

## Проверка устойчивости

Два варианта RandomForest дополнительно проверены на fold 1 и 2 того же `StratifiedGroupKFold`: seed 42, 5 частей, одинаковые строки для двух моделей внутри каждого fold. Проверочные ID разных частей не пересекаются. Схема не выбирает другую часть, если в запрошенной отсутствует класс: в таком случае эксперимент завершается понятной ошибкой.

| Fold | Проверочных строк | Worms в проверке | `balanced_subsample` | `balanced` | Разница Macro F1 |
| --- | --- | --- | --- | --- | --- |
| 0 | 17 515 | 16 | 0.5936013845 | 0.6009466538 | +0.0073452693 |
| 1 | 17 924 | 14 | 0.5678427903 | 0.5743204455 | +0.0064776552 |
| 2 | 17 522 | 8 | 0.6027644354 | 0.5872349885 | **−0.0155294469** |

На третьей проверке `balanced` ухудшил результат; в том числе правильно найдены 2 из 8 Worms вместо 3. **Устойчивое преимущество не подтверждено; стандартные настройки и план автоподбора сохранены.** Это сравнение трёх частей, не полная средняя оценка 5-fold CV. Между частями абсолютные оценки зависят от состава проверки; варианты сравниваются внутри каждой части.

Повторение дополнительных проверок:

```powershell
.\.venv\Scripts\python.exe experiment_classification_weights.py data/classification/task.md --fold-index 1 --recipes rf_control rf_balanced --output-dir delivery/experiments/weights-fold1
.\.venv\Scripts\python.exe experiment_classification_weights.py data/classification/task.md --fold-index 2 --recipes rf_control rf_balanced --output-dir delivery/experiments/weights-fold2
```

Для повторного запуска укажите новое имя папки. Все дополнительные метрики независимо пересчитаны из CSV; хеши входных файлов сохранились, API не использовался.

## Ограничения

- Проверочные группы исключают попадание точных копий между обучением и проверкой, но не гарантируют отсутствие других зависимостей между строками.
- Среди одинаковых признаков встречаются разные правильные ответы. Это ограничивает разделимость таких строк; из этого анализа не следует точный потолок Macro F1.
- Разбиения и варианты используются для исследования. Полученные цифры не заменяют проверку скрытого test; лучший локальный вариант не гарантирует лучший результат платформы.
- Настройки автоподбора и стандартных моделей в этой версии сохранены. Вес можно проверить отдельным запуском через «Изменить настройки», сохранив прежнюю схему проверки.
