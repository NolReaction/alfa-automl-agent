# Macro F1: отдельное правило выбора классов

База: `95dcb6c2f52ee3bacd7c83fe041f77c25ec65cdf`. Ветка:
`work/gpt-macro-f1-rules`. Исследование изолировано от конкурсного runtime.
Новые правила не подключаются автоматически; API calls: **0**.

## Проверяемая гипотеза

Обычный `argmax(p)` не оптимизирует Macro F1 напрямую. Проверяем правило
`classes[argmax(p * multipliers)]`: положительные множители выбираются только
по calibration-вероятностям и разрешённым calibration-ответам. Контроль и
кандидат используют одну уже обученную модель и одинаковые внешние строки.
Это исследование решений по вероятностям, а не повторный подбор class weights.

До первой внешней оценки закреплены:

- seeds `73`, `119`, `2027` и три синтетических сценария;
- сетка множителей `[0.5, 0.75, 1, 4/3, 2]`, границы `[0.5, 2]`;
- последовательный coordinate search: максимум 3 раунда и 128 уникальных
  оценок, включая identity; seed поиску не нужен;
- минимум 100 calibration-строк и 10 наблюдений каждого объявленного класса;
- при равной метрике с допуском `1e-12` предпочтительнее identity, затем меньше
  изменённых координат, меньше сумма абсолютных логарифмов, затем
  лексикографический порядок множителей;
- один RandomForest: 160 деревьев, глубина 12, минимум 2 строки в листе,
  `max_features="sqrt"`, `class_weight="balanced_subsample"`, `n_jobs=8`.
  Random state равен заранее заданному seed случая.

Внешняя оценка не возвращается в настройку множителей, генераторов, порогов
поддержки или модели. После calibration модель не переобучается. Поэтому
распределение её вероятностей между calibration и audit не меняется из-за
refit. Обобщение правила на последующий полный refit здесь не проверено.

## Контракт модуля

```python
fit_decision_rule(probabilities, calibration_labels, classes, *, options=None)
predict_with_rule(probabilities, prediction_classes, rule)
```

```python
from agent.classification_decision import fit_decision_rule, predict_with_rule

rule = fit_decision_rule(calibration_p, calibration_y, model.classes_.tolist())
predicted = predict_with_rule(audit_p, model.classes_.tolist(), rule)
```

`classes` и `prediction_classes` явно задают порядок колонок. При применении
колонки переставляются в сохранённый canonical order до `argmax`, включая
равенства вероятностей. Строки `01`, `NA`, `class c` сохраняются буквально.
Вероятности должны иметь форму `(n, K)`, быть конечными, лежать в `[0, 1]`
и суммироваться в 1 с абсолютным допуском `1e-6`.

Результат fit — конечный JSON-совместимый объект: `version`, `metric`,
`classes`, `multipliers`, `options`, `diagnostics`. Diagnostics сохраняют
число строк, поддержки классов, число оценённых кандидатов/раундов, причину
остановки, fallback и обе calibration-метрики. Даже с явными options действуют
жёсткие пределы: 10 раундов, 4096 кандидатов, 33 значения сетки.

Пустая calibration `(0, K)`, отсутствующий класс, менее 100 строк или менее
10 наблюдений класса дают identity с явной причиной. Неверные входы и
повреждённый JSON отклоняются, а не исправляются молча. Пустая calibration
может обозначать невозможность корректного внутреннего разбиения.

Модуль не видит исходных признаков и не способен доказать независимость
calibration. Host обязан заранее закрепить group/time policy, исключить
пересечение исходных признаков и обучать preprocessing только на fitting.
Невозможный group/time split нельзя заменять случайным. Модуль не читает
файлы, окружение, API или внешние ответы.

Правило меняет только метки для **Macro F1**. Вероятности LogLoss/ROC AUC
остаются исходными. Это ограничение назначения, а не автоматическая проверка
метрики host: вызывающая сторона должна явно проверить metric.

## Воспроизводимость и результаты

Три заранее заданных сценария:

| Сценарий | Fit / calibration / audit | Разделение |
| --- | --- | --- |
| Несбалансированные перекрывающиеся классы | 675 / 225 / 225 | Группы исходных признаков, без перебора разбиений |
| Дубли с противоречивыми ответами | 720 / 240 / 240 | 300 групп по 4 строки; группы целиком в одной части |
| Категории, неизвестные значения и сдвиг | 675 / 225 / 225 | Последовательно по времени: 0–674 / 675–899 / 900–1124 |

В первом случае заданы доли классов `0.74/0.20/0.06`, `class_sep=0.8`,
`flip_y=0.04`. Во втором ответы копий независимо выбираются из распределения
группы, поэтому одинаковые признаки могут иметь разные метки. В третьем
неизвестная категория появляется только во внешней части с вероятностью 0.35,
а logits классов получают заранее заданный сдвиг `[0, -0.4, 0.4]`.
Параметры генераторов и их исходники фиксируются хешами, а не подбираются
после просмотра внешних метрик.

Numeric imputer и categorical imputer/OneHotEncoder обучаются только на fit.
Неизвестные категории обрабатываются через `handle_unknown="ignore"`.
Код проверяет отсутствие пересечения строк/групп исходных признаков во всех
трёх частях. Для временного случая дополнительно проверяется порядок периодов.

Запуск в два шага фиксирует исходники, конфигурацию, версии окружения и все
случаи до обучения. Укажите новое имя каталога:

```bash
python experiment_classification_decision.py --prepare-only --output-dir data/experiments/classification_decision/run-001
python experiment_classification_decision.py --run-prepared data/experiments/classification_decision/run-001
```

Можно добавить `--public-task data/classification/task.md` на первом шаге:
тогда дополнительно выполняются заранее заданные grouped folds 0, 1, 2
существующей схемы. Fitting/calibration внутри outer-train также разделены
по raw-группам. Неподходящая метрика или невозможный split дают ошибку, а не
другую более выгодную проверку. При отсутствии стандартного публичного task
синтетика завершается с явным `skipped_missing_data`.

`preregistration.json` сохраняется до первого audit. Для каждого случая до
scoring сохраняются `frozen.json`, JSON-правило и снимок модели. В результатах
есть source/split/ID/prediction SHA-256, размеры/поддержки, обе метрики,
per-class precision/recall/F1, timings и ресурсы. CSV/модели остаются в
игнорируемой папке результатов. Повторный запуск в тот же каталог запрещён;
изменение исходников или окружения после prepare отклоняется.

Worker-процессы выполняются последовательно: максимум 8 потоков, 600 секунд
на процесс. Сумма timeout-бюджетов равна 5400 секундам для синтетики или
7200 секундам с public, плюс запуск управляющего процесса и сериализация
его отчёта. На Linux используется лимит виртуального адресного пространства
32 GiB (`RLIMIT_AS`); это не эквивалент контейнерного ограничения RSS.
Пиковый RSS измеряется отдельно через `getrusage(RUSAGE_SELF).ru_maxrss`,
охватывает жизнь worker, включая fit, и исключает supervisor. Недоступность
ограничения или измерения записывается явно. Windows-исполнение здесь не
подтверждается.

Профильные проверки: **48 тестов прошли**, из них 23 новых. Они проверяют
alignment, canonical tie-breaks, identity, точные строковые классы, JSON,
некорректные входы, поддержку редких классов, пределы поиска, воспроизводимость
генераторов, group/time boundaries и неизвестные категории. Mocked worker
доказывает порядок freeze до audit и неизменность правила/предсказаний при
изменении только audit-ответов. Реальное измерение синтетики проведено
отдельно. Полный CI, Windows и полный конкурсный runner в этой ветке не
перепроверялись.

После измерения независимая проверка пересчитала все 9 пар из сохранённых
CSV: Macro F1, per-class precision/recall/F1/support, calibration-метрики,
контрольный argmax, прогнозы с множителями, ID/разбиения и хеши модели/правила.
Совпадение с допуском `1e-12`, ошибок 0; модели повторно не обучались.
CSV читались с `keep_default_na=False` и `float_precision="round_trip"`.

Возможная точка интеграции — host-рецепт классификации после разрешённого
внутреннего fit/predict_proba и до формирования **меток**. Он должен:

1. Проверить, что основная метрика именно Macro F1.
2. Получить calibration только из собственного fitting-пула с закреплённой
   group/time policy; при невозможности вернуть identity.
3. Вызвать `fit_decision_rule(p_cal, y_cal, probability_classes)` и включить
   возвращённый JSON в замороженный рецепт, учитываемый его хешем.
4. Во внешнем predict вызвать `predict_with_rule(p, probability_classes, rule)`.
   Внешние ответы в fit не передавать.
5. До полного host refit отдельно проверить перенос правила на новое
   распределение вероятностей. Текущий эксперимент этот перенос не проверяет.

С учётом шести ухудшений **сейчас подключать правило к стандартному runtime
не рекомендуется**. Новый способ регуляризации/отбора или его включения
нужно фиксировать заранее и проверять на ещё не просмотренных данных.
Эти девять audit-частей после данного исследования уже просмотрены.

Изменены только пять новых файлов из ТЗ. `solution.py`, AutoML, runner,
