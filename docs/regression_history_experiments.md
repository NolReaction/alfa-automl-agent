# Исторические признаки зданий в регрессии: матрица экспериментов

Вопрос: какое применение истории по ключу здания устойчиво помогает моделям регрессии (`site_eui`, RMSE, меньше лучше). Все цифры — локальная проверка на train, не баллы платформы. Ключ `State_Factor, building_class, facility_type, floor_area, year_built, ELEVATION` — эвристика, а не доказанный идентификатор здания.

## Итог

- Смесь «0.5 × модель + 0.5 × среднее прошлых ответов ключа» улучшает RMSE во всех трёх проверках для всех четырёх моделей, на которых её проверяли. Лучшая по общей оценке: ExtraTrees без `Year_Factor` со смесью — **47.33** против 49.07 без смеси и 49.26 у нашего ExtraTrees со всеми признаками.
- История как обучаемый признак устойчива не везде. У HistGradientBoosting (HGB) она улучшает результат во всех трёх годах (лучший результат года 5: **44.38**). У ExtraTrees она почти не меняет год 3 (−0.04), помогает в году 4 (−2.73), но ухудшает год 5 (49.22 против 47.63).
- Рекомендуем для подключения один вариант: ExtraTrees без `Year_Factor` плюс фиксированная смесь с историей (`blend_et_no_period`). Он не требует нового обучения и не зависит от того, как мало истории у обучающих строк.
- Это не обещание улучшить скрытый тест: год 5 мы изучали раньше, доверительные интервалы здесь не считались, вес смеси не подбирался.

## Как повторить

Данные: `python prepare_data.py regression`. Окружение: Python 3.12, версии из `requirements.txt`. Из корня проекта, около 2 минут на ноутбуке автора (Windows, 8 потоков):

```
.\.venv\Scripts\python.exe experiment_regression_history.py
.\.venv\Scripts\python.exe -m unittest tests.test_building_history
```

Результаты скрипт пишет в `data/experiments/regression_history/` (папка `data/` не попадает в Git): `metrics.json` (всё, включая параметры и списки признаков), `metrics.csv`, `predictions_year3|4|5.csv` (текстовые `id`, ответ, история, прогноз каждого варианта; читать с `dtype={"id": str}`), `input_hashes.json`. SHA-256 всех файлов в папке данных и любого `submission.csv` рядом проверяется до и после запуска; при расхождении скрипт завершается ошибкой. Папка результатов не может лежать внутри папки данных. Seed 42, не более 8 потоков.

## Что именно проверялось

Для года `t` модели обучаются на строках периодов `< t` и проверяются на строках периода `t`; строки проверки одни и те же для всех вариантов. Для каждого года создаётся новый `HistoryEncoder`: `fit_transform` на обучающих строках, `transform` на проверочных. История считается до удаления `Year_Factor` из признаков модели. Для строки периода `p` используются только ответы периодов строго меньше `p`, в том числе для обучающих строк (собственный ответ, тот же год и будущее не видны; тесты в `tests/test_building_history.py`, включая сквозной: изменение ответов года 5 не меняет ни прогнозы, ни историю).

| № | Вариант | Модель | `Year_Factor` | История |
| --- | --- | --- | --- | --- |
| 1 | `hgb_all` | HGB baseline (`max_iter=150`, `max_leaf_nodes=31`, `learning_rate=0.1`) | да | нет |
| 2 | `hgb_no_period` | то же | нет | нет |
| 3 | `hgb_no_period_history` | то же | нет | 5 признаков |
| 4 | `et_all` | ExtraTrees 200 деревьев, `min_samples_leaf=1`, `max_depth=None`, `max_features=1.0` | да | нет |
| 5 | `et_no_period` | то же | нет | нет |
| 6 | `et_no_period_history` | то же | нет | 5 признаков |

Смеси `blend_*` строятся из прогнозов вариантов 1, 2, 4, 5 без нового обучения: при наличии истории `0.5 × модель + 0.5 × среднее истории`, иначе прогноз модели. Конвейер подготовки — `make_pipeline` из `offline_baseline.py` (медианное заполнение пропусков), у ExtraTrees заменён только шаг модели. Поэтому у вариантов с историей пропуск `history_mean` заполняется медианой по обучающим строкам, где история есть; флаг `history_present` остаётся признаком.

## Откуда выигрыш и ухудшение

- **Смесь.** Выигрыш целиком на строках с историей (22.6% строк): их RMSE падает с 37.6 до 25.9 у ExtraTrees. Строки без истории по построению не меняются. На строках с историей одно среднее прошлых ответов ключа (RMSE 28.68) точнее ExtraTrees (37.58), а смесь 50/50 точнее обоих (25.89). Сильнее всего эффект в году 4, где история есть у 36.5% строк.
- **Признаки у HGB.** Помогают во всех годах, но часть выигрыша приходится на строки без истории (год 5: 49.91 → 46.39). Значит, модель использует `history_present` и счётчики как косвенные признаки, и приписывать весь выигрыш самим историческим значениям нельзя.
- **Признаки у ExtraTrees.** В году 5 история ухудшает результат на строках без истории (49.03 → 51.74) и всё равно сильно помогает там, где она есть (40.79 → 35.92). Вероятная причина — разное распределение истории: в обучении она есть у 5–19% строк (у строк первого обучающего года её нет по построению), в проверке у 13.5–36.5%. Модель учится на данных, где история встречается реже и по-другому, чем будет применяться. У смеси такого сдвига нет. Это объяснение, а не доказанный механизм: отдельно мы его не проверяли.
- **Без `Year_Factor`.** Небольшое улучшение у ExtraTrees во всех трёх годах (−0.16…−0.23) и заметное у HGB только на году 5. Скрытый тест — год 6, которого нет в обучении, поэтому деревья всё равно не могут опираться на значение периода; это довод в пользу удаления, но не доказательство.

## Ограничения и стоимость

- Год 5 изучали раньше, он не независимый тест. Три проверки используют перекрывающиеся данные и разные размеры обучения (год 3 — всего два года обучения).
- Доверительные интервалы и повторные seed не считались; RMSE определяется небольшим числом больших значений цели (`docs/data_notes.md`), поэтому разницы порядка 0.2 на одном году мы значимыми не считаем. Устойчивым считаем знак изменения во всех трёх годах.
- Вес смеси 0.5, параметры HGB и ExtraTrees не подбирались. Сочетание «признаки истории + смесь» не проверялось.
- Ключ — эвристика; неоднозначность видна только при повторе внутри года, между годами её не видно.
- В скрытом тесте (год 6) история из годов 1–5 есть примерно у 37.5% строк (оценка из `docs/building_history_report.md`), то есть ближе к году 4, чем к году 5. Это не обещание такого же выигрыша.
- Стоимость на ноутбуке автора. Признаки истории: 0.19 / 0.33 / 0.62 с за годы 3 / 4 / 5. Обучение HGB 0.8–1.9 с; ExtraTrees 2.7 / 9 / 19 с без истории и 3.4 / 12 / 25 с с историей; предсказание не больше 0.3 с. Вся матрица — около 2 минут. Смесь не стоит ничего, кроме расчёта истории.

## Рекомендация

Подключать **`blend_et_no_period`**: ExtraTrees (наши параметры) без `Year_Factor` и смесь 0.5 / 0.5 с историей там, где она есть. Причины: лучшая объединённая оценка (47.33), улучшение к той же модели в каждом из трёх годов, нет зависимости от доли истории в обучающих строках, нет дополнительного обучения. Что нужно для интеграции (в приложение мы это не подключали):

1. Для каждой схемы проверки создавать новый `HistoryEncoder(KEY, "Year_Factor", numeric_columns=("floor_area", "year_built", "ELEVATION"), positive_columns=("year_built",))`: `fit` на обучающей части, `transform` на проверочной. Для итогового прогноза — `fit` на всём train, `transform` на test.
2. Передавать в encoder таблицу с `Year_Factor`, а из признаков модели его удалять.
3. После `predict` применить смесь (сейчас функция `blend` лежит в `experiment_regression_history.py`; при подключении её надо вынести в модуль).
4. Решить, как автоподбор узнаёт столбцы ключа и период; при их отсутствии историю не применять. Период должен быть числовым и упорядоченным по времени, иначе «строго прошлое» не определено.
5. `hgb_no_period_history` стоит иметь в виду как второго кандидата: он лучший на году 5 и устойчиво лучше своего HGB, но слабее ExtraTrees по сумме.
