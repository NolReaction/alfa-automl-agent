## Как передаём работу

1. Каждый начинает свою ветку от указанного коммита, предварительно проверив локальные изменения. Никаких force-push, reset чужой работы или прямых коммитов в `main`.
2. После аудита фиксирует краткий план и исходные измерения в своём отчёте. Затем реализует минимальный работающий вариант, измеряет слабые места и дорабатывает его. Не меняет критерии задним числом ради победы.
3. В Git попадают исходники, тесты и компактный отчёт. Полные предсказания, логи и манифесты экспериментов сохраняются локально в `data/experiments/<своя-ветка>/`; в отчёте — команды, расположение и хеши. Крупные данные, модели, ключи и окружение не коммитятся.
4. В PR указывает базовый commit, изменённые файлы, фактически выполненные проверки, сравнение до/после, ограничения и точку подключения. Если помощник не может запускать код, человек выполняет команды и возвращает вывод; непроведённая проверка так и называется.
5. Каждый открывает отдельный PR в `main` для просмотра. Автоматическое слияние не включаем. Дима сначала проверяет совместимость в своей интеграционной ветке, затем капитан принимает PR в согласованном порядке. Слияние модулей и включение нового поведения — отдельные шаги.

Рекомендуемый порядок подключения: Ника → Таня → Мурад. Это порядок интеграции, **не очередь начала работы**. Сначала стабилизируем контекст и протокол исследования; затем подключаем проверенные рецепты; историю включаем только для явно подходящей схемы и после временной проверки.

## Вычисления и API

Мурад и Таня работают без командного API. Ника сначала выполняет offline replay и protocol tests; реальные запросы — после подключения общего контроля бюджета Димой. Общий лимит разработки из инструкции организаторов — 600 ₽/сутки, сброс в 03:00 МСК; это не лимит каждому. Перед реальными запусками Ника и Дима согласуют расход между собой. Токены без тарифа не переводим в рубли, отсутствующий usage не считаем нулевым расходом.

Claude помогает писать и анализировать код. Подписка участника не заменяет конкурсный API и не меняет backend решения. Ключ не передаём в задания, отчёты, тесты или Git. Долгие обучения ограничиваем по времени и выполняем последовательно на каждой машине, максимум 8 вычислительных потоков в одном запуске.
