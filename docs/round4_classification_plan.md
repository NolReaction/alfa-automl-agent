## Данные, изоляция и предварительное покрытие

Используются официальные неизменные TRAIN/TEST и словарь данных. До обучения manifest сохраняет их SHA-256, версии Python/пакетов, фактический source/recipe/runtime, порядок гипотез и все split hashes. TEST без меток, его строки не формируют статистики обучения или правила решений.

Внешний screening — grouped seed **42**. Confirmation — заранее заданные grouped seeds **43, 44, 137**. Внутри каждого разрешённого fit: A/B строятся штатным `split_rows` с grouped policy и seed **42**; внутри A — ровно **3 StratifiedGroupKFold**, `shuffle=True`, seed **42**. Индексы фиксируются до моделей; при недостаточном покрытии их не заменяют удобным split. Все группы определяются по исходным признакам без ID/target **до преобразований и расчёта весов**.

До моделей записываются строки и число различных feature-групп каждого класса на внешнем fit, A, B и обеих частях каждого OOF fold. Нулевое пересечение групп обязательно на каждой границе. Дубли и противоречивые метки одной feature-группы не разделяются. Требования существующего guarded decision сохраняются, включая минимум 5 строк каждого класса в A/B; известный дефицит допуска вызывает preflight identity с точной причиной до OOF fits. Missing class в обучающем fold, неполное покрытие, невозможный безопасный split и ошибки вероятностей не исправляются внешними ответами.

Вероятности получают настоящим `predict_proba` через новый изолированный adapter; их не восстанавливают из labels и не подменяют метрику задачи. Внешний v3-кандидат возвращает обычные Macro F1 labels. Все преобразования/веса/OOF-правила обучаются заново только на текущем fitting subset. OOF probability matrix можно повторно анализировать лишь при неизменных модели, preprocessing и training weights.

## Screen: identity и пять гипотез

Порядок фиксирован таблицей. Это полные recipes, без последующего перебора комбинаций. У всех базовых моделей фиксированное число деревьев, без дополнительного early-stopping/refit цикла. Один физический fit означает один вызов обучения одной компоненты; начатый неуспешный fit тоже учитывается.

| Порядок | Проверка / механизм | Максимум физических fits |
| --- | --- | ---: |
| C0 | Штатный `BASELINE_SOURCE` с фиксированным сильным рецептом — свежий reference | 2 |
| C1 | Тот же рецепт через probability adapter, identity/argmax; проверка точного совпадения labels с C0 и class order. Его wall time служит cost probe | 2 |
| H1 | Guarded OOF decision поверх того же FixedBlend: три fold в A, один A→B, новый fit на всём разрешённом fit. Механизм — ограниченное изменение границ решений и TP/FP | 10 |
| H2 | Тот же FixedBlend + fit-only category frequencies для трёх объявленных категориальных признаков. Механизм — различать распространённые/редкие категории без target encoding | 2 |
| H3 | Тот же FixedBlend + одно семейство из трёх направленных числовых асимметрий. Механизм — прямые пороги деревьев по относительному направлению потока | 2 |
| H4 | Тот же FixedBlend + ограниченные fit-only веса повторяющихся raw feature-групп. Механизм — уменьшить влияние многочисленных одинаковых наблюдений | 2 |
| H5 | `ExtraTreesClassifier` на representation H3: 300 деревьев, `max_depth=18`, `min_samples_leaf=4`, `max_features="sqrt"`, `class_weight="balanced"`. Механизм — более регуляризованные случайные разбиения; отдельно сравнить с H3 | 1 |
| Итого | Плановая верхняя стоимость успешных исходов | **21** |

**Hard cap screen — 24 физических fits**, включая начатые и неуспешные. Автоматических retries и дополнительных гипотез нет; свободный запас не превращается в новый подбор. При preflight identity у H1 — 0 calibration fits и до 2 final fits. Отказ H1 не отменяет H2–H5. Неудачные/пропущенные исходы сохраняются с причиной.

H1 использует **неизменённые `DEFAULT_GUARD_OPTIONS`**: grid `[0.8, 1, 1.25]`, regularization `0.01`, минимум admission gain `0.01`, максимум падения F1 класса `0.02`; минимум A/B — 100/60 строк и 5 строк каждого класса; 2 раунда, максимум 128 candidates. На OOF_A выбирается одно правило; B только принимает его или identity. B не меняет множители. Сохраняются counts фактически обученных, принятых и применённых правил; identity не называется полезной калибровкой.

H2 использует существующее значение `log1p(count_fit(category))`; unknown — **0**. Ровно три categorical columns задаются экспериментальной схемой; словарь строится на fitting rows каждого fold, без prediction rows и без меток. Дополнительного редкостного порога или выбора столбцов нет.

H3 — **ровно одно числовое семейство**, направленная асимметрия `(forward − reverse)/(forward + reverse)`. Словарь явно задаёт пары `(sbytes, dbytes)` в байтах, `(spkts, dpkts)` в пакетах, `(sload, dload)` в bit/s. Это совместимые величины одного направления измерения; результат безразмерный, в `[-1, 1]`, максимум **3** новых столбца. Имена публичных столбцов находятся только в экспериментальном recipe; runtime получает объявленные пары, quantity/unit/direction и проверяет схему, не угадывая их по имени или корреляции. При двух нулях результат 0; отрицательные, NaN и бесконечные значения дают NaN для штатной missing policy компоненты. Для больших конечных значений сначала обе величины делятся на их максимум, чтобы сумма/разность не переполнялась. Квантилей и отбираемых по ответам пар нет. В отличие от монотонного signed-log, такое взаимодействие меняет геометрию доступного дереву разделения.

H4: для каждой raw feature-группы размер `n_g` вычисляется **только на текущем fitting subset**. `u_i = max(0.25, 1/sqrt(n_g))`, `w_i = u_i / mean_fit(u)`. Отношение максимального веса к минимальному не больше 4; формула и cap не подбираются. Обе компоненты получают `model__sample_weight`; исходные `class_weight` сохраняются. Метки не определяют group multiplier, противоречивые строки одной группы получают одинаковый множитель. В evidence — histogram размеров групп, raw/effective class masses, min/max weights. Ожидаемый эффект проверяется через FP и confusion; возможная потеря редких TP также публикуется.

## Время и ресурсы

Обычный trial — **300 с**, H1 OOF trial — **600 с**, один OOF callback — максимум **90 с**. Callback обучает две компоненты последовательно. Reserve на final fit/predict — **120 с**. Все подготовка, copies, predictions и проверки входят в исходный абсолютный deadline; child/callback timeout не создаёт нового бюджета. Callback `.fit()` реально ограничивается существующим процессным supervisor, а не только аргументом Python-функции.

До OOF используется измеренное полное wall time C1 (`probe`): допуск только если `4 * probe * 1.5 + max(120, 2 * probe) <= 600`. Иначе — явный `cost_admission` skip/identity без дополнительных probe fits. Во время исполнения дополнительно соблюдаются фактический callback timeout и оставшийся final reserve; поздний или неполный OOF не применяется. Несовпадение identity C0/C1 — контрактная ошибка, дальнейший вывод о качестве adapter не допускается до исправления и нового плана измерений.

Все тяжёлые arms выполняются последовательно, максимум **8 вычислительных потоков на весь набор процессов**. Фактический общий cgroup: **8 CPU / 8 GiB**, это не квалификация конкурсных 32 GB. Process-tree RSS/cleanup при недоступном мониторе — `null/unknown`, с причиной. Если доступен self-RSS дочернего процесса, он записывается отдельно и не выдаётся за peak RSS всего дерева. API отсутствует; происхождение нулевых counters фиксируется. Официальные dependencies не меняются; версии среды сохраняются в manifest.

## Выбор финалиста и confirmation

После screen выбирается **один** успешный challenger с наибольшим внешним screen Macro F1. При равенстве — порядок H1…H5. H1 с identity или без фактического применения неidentity-правила исключается из выбора challenger. Выбранный вариант проходит confirmation даже при отрицательной screen-разнице: результат нельзя скрыть, выбирая удобное условие продолжения. Если подходящего успешного challenger нет, фиксируется `retain_incumbent`, без подмены кандидата новой гипотезой.

До первого confirmation source/recipe/options финалиста замораживаются. На каждом seed **43/44/137** заново обучаются фиксированный контроль и финалист с теми же ресурсами и внутренними правилами. Нет переноса fitted-словарей, моделей, весов или решений между seeds. Максимум confirmation: **36 fits** = `3 × (control 2 + OOF finalist 10)`. Для обычного двухкомпонентного финалиста — **12**, для H5 — **9**. Лимит screen не покрывает confirmation.

Основной критерий считается **только по трём confirmation-срезам**, screen 42 публикуется отдельно:

- средний paired Δ Macro F1 **≥ +0.003**;
- на каждом confirmation-срезе Δ Macro F1 **≥ −0.01**;
- на каждом confirmation-срезе Δ F1 каждого класса **≥ −0.05**;
- средний суммарный вклад остальных классов в macro delta после исключения глобально редчайшего класса должен быть **положительным**. Редчайший класс определяется один раз по class counts полного TRAIN до обучения (при равенстве — объявленный class order). Это дополнительная проверка устойчивости; основная Macro F1 всегда включает **все** классы.

Публикуются TP/FP/FN/support, per-class F1, вклад каждого класса `ΔF1_class / K`, confusion и разброс на всех заданных срезах. Никаких исключённых неудачных seeds. Confirmation не меняет параметры; новый вариант требует нового development-плана. Непрохождение любого условия означает сохранить incumbent, без заявления нового default.
