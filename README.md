# AI-агент для хакатона Альфа-Будущее

Стартовый проект команды. Его первая цель — проверить окружение, подключить выданную Qwen и запустить агента на материалах задачи. Это ещё не готовое конкурсное решение: качество моделей и полный запуск нужно проверять отдельно.

## Первый запуск на Windows

Нужен **Python 3.12**. Открой PowerShell в папке проекта и выполни команды по очереди:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe solution.py --check
```

Если `.env` уже существует, пропусти команду `Copy-Item`, чтобы сохранить свои настройки. Активировать окружение и менять политику выполнения PowerShell не требуется: команды напрямую используют Python из `.venv`.

`--check` работает **без интернета и API-ключа**. Он проверяет версию Python, наличие нужных пакетов и запуск отдельного процесса Python. Эта проверка не обучает модель и не подтверждает, что агент уже решает задачу. Для первоначальной установки пакетов интернет нужен.

Если `py -3.12` не найден, сначала установи Python 3.12 и заново открой PowerShell.

На macOS или Linux с установленным Python 3.12 те же шаги выглядят так:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp -n .env.example .env
.venv/bin/python solution.py --check
```

Для остальных команд ниже на macOS/Linux используй `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

## Подключение Qwen

Открой `.env` в корне проекта и заполни три поля данными, выданными организаторами:

```dotenv
OPENAI_API_KEY=
OPENAI_BASE_URL=
OPENAI_MODEL=
```

| Поле | Что указать |
| --- | --- |
| `OPENAI_API_KEY` | Выданный API-ключ |
| `OPENAI_BASE_URL` | Выданный адрес API |
| `OPENAI_MODEL` | Точное имя доступной модели Qwen |

Названия переменных совместимы с форматом OpenAI API; здесь в них указываются настройки выданной Qwen. Не угадывай адрес или имя модели. Если данных ещё нет, пока достаточно проверки `--check`.

Когда настройки получены, можно отдельно проверить подключение:

```powershell
.\.venv\Scripts\python.exe solution.py --check-api
```

Эта команда отправляет короткий запрос и расходует немного токенов из общего лимита команды. Обычная проверка `--check` запросов не отправляет. Файл `.env` с ключом не добавляем в Git. Если такие же переменные уже заданы в окружении системы, они имеют приоритет над `.env`.

## Где взять и куда положить задачи

Материалы организаторов: [официальная папка с данными](https://drive.google.com/drive/folders/1eUjfuovujgEoUbtotU9uRGWLo-RacY3T?usp=sharing).

Скачай и распакуй материалы вручную:

| Задача | Файл условия | Папка с CSV |
| --- | --- | --- |
| Регрессия | `data/regression/task.md` | `data/regression/regression/participants/` |
| Классификация | `data/classification/task.md` | `data/classification/multiclass/participants/` |

В каждой указанной папке с CSV должны находиться `train.csv`, `test.csv`, `data_dictionary.csv` и `sample_submission.csv` соответствующей задачи. Сохраняй вложенные папки: пути к данным внутри `task.md` указаны относительно самого Markdown-файла, поэтому CSV не нужно переносить прямо к нему. Двойное `regression/regression` в пути выше соответствует этому размещению. Публичные материалы и данные в репозиторий не коммитим.

## Запуск агента на задаче

Из корня проекта запусти одну задачу:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md
```

Или вторую:

```powershell
.\.venv\Scripts\python.exe solution.py data/classification/task.md
```

Для этих запусков нужны заполненные настройки Qwen. Агент запускает Python-код напрямую, без отдельного MCP-сервера. Рабочей папкой для вычислений становится каталог выбранного `task.md`, поэтому задачи держим в разных папках. Настройки `.env` при этом читаются из корня проекта.

Для публичной регрессии результат должен появиться в `data/regression/submission.csv`, для классификации — в `data/classification/submission.csv`. Имя файла, столбцы и порядок строк заданы в соответствующем `task.md`.

Агент ограничен 12 обращениями к модели и 175 минутами работы; один эксперимент ограничен 30 минутами и оставшимся общим временем. Денежный остаток API этот стартовый код не рассчитывает. Если модель сообщает о завершении, отдельный код проверяет `submission.csv`: столбцы и порядок ID, число строк, пустые значения, конечные числа или допустимые классы. При ошибке агент получает описание проблемы и может исправить файл. Проверка формата не измеряет качество модели.

Скрипты экспериментов и их вывод сохраняются в `.agent_runs` рядом с `task.md`. Каждый эксперимент выполняется в отдельном процессе с рабочей папкой задания. Этот механизм не является изолированной файловой или сетевой песочницей; запускай агента на подготовленных материалах задачи.

Точка входа — `solution.py`: первым аргументом передаётся путь к описанию задачи, как в baseline организаторов. Если аргумент не указан, используется `task.md` в текущей папке. Перед сдачей нужно отдельно проверить весь запуск и соответствие итогового файла требованиям задачи; успешного `--check` для этого недостаточно.

## Проверки разработчика

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют временные данные и локальную имитацию API. Реальная Qwen не вызывается, токены команды не расходуются. Тест с локальным API проверяет настоящий SDK, обучение простой модели и запись CSV; это не оценка качества на задачах организаторов. Проверки в текущей среде выполнялись на Linux; запуск на Windows нужно подтвердить на компьютере участника.

## Ближайшие шаги команды

1. Каждому выполнить `--check`; Ивану собрать ошибки запуска и помочь получить одинаковое рабочее окружение.
2. Мураду проверить материалы задач, Татьяне — воспроизвести базовое обучение и проверку качества.
3. Диме и Нике соединить работу с Qwen, выполнение кода и сравнение результатов в один полный запуск; затем вместе проверить файл предсказаний перед первым сабмитом.
