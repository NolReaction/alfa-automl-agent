# AI-агент для хакатона Альфа-Будущее

Я Дима, капитан команды. Здесь собираем агента, который читает условие ML-задачи, пишет и запускает Python-код, сравнивает эксперименты и сохраняет предсказания в `submission.csv`.

## Alfa Lab — приложение команды

В Alfa Lab можно работать с данными и запускать эксперименты из браузера: обучать baseline и ExtraTrees, смотреть этапы и журналы, сравнивать метрики, выбирать предсказания и обмениваться отчётами. После настройки API здесь же запускается исследование с Qwen.

| Экран | Для чего нужен |
| --- | --- |
| Данные | Посмотреть состав таблиц, распределение классов и различия train/test |
| Запуски | Обучить модель, увидеть результат проверки и следующий шаг |
| Результат | Сравнить эксперименты, скачать CSV и отчёт, собрать конкурсный `solution.zip` |

После [подготовки окружения](#как-запустить-у-себя) на Windows откройте `app/AlfaLab.exe` двойным кликом. Откроется окно управления и панель в браузере. EXE использует Python и библиотеки из `.venv` проекта. Можно также открыть `app/start-app.bat` или выполнить из корня проекта:

```powershell
.\.venv\Scripts\python.exe app/server.py --open
```

Для первого знакомства выберите задачу → **«Обучить baseline»** → **«Сравнить с ExtraTrees»**. В разделе **«Результат»** выберите удачный запуск кнопкой **«Использовать CSV»**. Эти две модели обучаются без API. Qwen расходует общий бюджет команды.

В окне обучения можно выбрать случайную проверку, последний период для регрессии или группы одинаковых строк для классификации. Сравнивайте модели при одинаковой схеме; её название и параметры сохраняются в истории и отчётах. [Подробнее о выборе проверки](app/README.md#выбор-проверки-модели).

Для нового эксперимента нажмите **«Изменить настройки»** у завершённого запуска: рецепт и проверка перенесутся, а параметры модели можно изменить перед обучением. Каждый вариант сохраняется отдельно вместе с метрикой и настройками. В «Результате» у каждой схемы проверки своя группа сравнения. [Как работать с настройками](app/README.md#эксперименты-с-настройками).

Каждый участник запускает свою локальную лабораторию. **«Скачать пакет запуска»** сохраняет ZIP с CSV и отчётом; коллега добавляет его через **«Добавить отчёт коллеги»**, без распаковки. Автоматической синхронизации между компьютерами пока нет.

Подробности: [инструкция Alfa Lab](app/README.md). История находится в `app/.workspace/`: сохраняйте её при обновлении приложения. На конкурс сдаём архив агента; панель в него не включается.

## Как работаем

1. Перед началом обновляем `main` и создаём свою ветку, например `work/nika-qwen`.
2. Пишем в Telegram, какую задачу и какие файлы берём. Если нужен файл, который уже меняет другой человек, сначала договариваемся.
3. Работаем в своей ветке. Коммиты пишем понятно на русском: что конкретно изменили.
4. Выполняем `dev_check.py` и открываем Pull Request в `main`. В описании указываем результат, команду проверки и оставшиеся проблемы. Я собираю изменения в `main`.
5. Если застряли, сразу присылаем команду запуска и полный текст ошибки. Когда работаем вместе, заходим в нашу комнату в Контур Толке.

В Git отправляем код и инструкции. `.env`, данные, результаты запусков и обученные модели в репозиторий не добавляем.

## Как запустить у себя

Клонируем [репозиторий](https://github.com/NolReaction/alfa-automl-agent) через PyCharm или Git. Нужен Python 3.12. Команды выполняем из корня проекта.

На Windows в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe dev_check.py
```

Если `.venv` уже создана на Python 3.12, первую команду пропускаем. В PyCharm выбираем интерпретатор проекта `.venv\Scripts\python.exe`. Активировать окружение в терминале не нужно.

На macOS/Linux:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python dev_check.py
```

Ожидаем `true` у версии Python, пакетов и `python_child`, затем `OK` после тестов. До получения ключа поля `api_settings_present` могут быть `false`. Эти проверки не обращаются к Qwen и не расходуют токены.

`dev_check.py` проверяет окружение, выполнение Python, обучение, сохранение CSV и восстановление после ошибок. Для тестов используется локальная имитация API. Эти же проверки настроены в GitHub Actions на Windows и Linux; результат смотрим во вкладке Actions.

## Первая модель без API

После загрузки данных:

```powershell
.\.venv\Scripts\python.exe offline_baseline.py data/regression/task.md
```

Скрипт отделяет 20% `train.csv` для проверки, обучает простую модель и печатает RMSE. Затем обучает модель на всём `train.csv`, сохраняет `data/regression/submission.csv` и проверяет его формат. Отчёт о качестве и времени сохраняется рядом в `baseline_metrics.json`.

Для классификации передаём `data/classification/task.md`; метрика будет Macro F1. Существующий `submission.csv` скрипт сохраняет: для явной замены нужно добавить `--overwrite`.

Это обычное обучение без Qwen и без расхода токенов. Полученный результат используем как точку сравнения для экспериментов агента.

## Когда придёт ключ

Я проверяю доступ первым. Ключ передаю команде лично, в репозиторий его не загружаем. У каждого в корне проекта должен быть локальный файл `.env`: копируем `.env.example`, если `.env` ещё нет, и заполняем данными организаторов.

```dotenv
OPENAI_API_KEY=ключ_организаторов
OPENAI_BASE_URL=адрес_API_организаторов
OPENAI_MODEL=точное_имя_модели
```

Проверка подключения на Windows:

```powershell
.\.venv\Scripts\python.exe solution.py --check-api
```

Команда делает один короткий запрос. У всей команды общий дневной API-бюджет в эквиваленте 600 рублей. Полные прогоны согласуем в Telegram, чтобы не запускать одинаковую работу одновременно.

После успешной проверки запускаем нужную задачу:

```powershell
.\.venv\Scripts\python.exe solution.py data/regression/task.md
.\.venv\Scripts\python.exe solution.py data/classification/task.md
```

На macOS/Linux заменяем `.\.venv\Scripts\python.exe` на `.venv/bin/python`.

Результат каждой задачи: `submission.csv` рядом с её `task.md`. Код экспериментов и их вывод: `.agent_runs` в той же папке. Агент проверяет формат CSV; качество отдельно оцениваем на своей валидации из `train.csv`.

## Что делает основной агент

1. Сохраняет копию уже готового корректного `submission.csv`. Если файла нет, пробует обучить стартовую модель в отдельном процессе, максимум 120 секунд в пределах общего времени.
2. Передаёт Qwen условие и сведения о стартовом результате. Запускает сгенерированный код и возвращает вывод и ошибки модели.
3. После эксперимента проверяет CSV. При ошибке кода или некорректном CSV восстанавливает последний корректный файл, если он был сохранён.
4. При ошибке API или достижении лимита сохраняет готовый ответ, если он есть. В отчёте такой запуск помечается `fallback`; это не успешный цикл исследования.

В `.agent_runs/<номер запуска>/run.json` записываются статус, шаги, ошибки, время и число запросов. Токены учитываются, если API возвращает `usage`; стоимость в рублях код пока не рассчитывает. Копия последнего корректного CSV хранится в той же папке. Корректный формат не гарантирует лучшее ML-качество.

## Как собрать архив

```powershell
.\.venv\Scripts\python.exe build_submission.py
```

Получаем `delivery/solution.zip`. Внутри: `solution.py` в корне, модули `agent/`, `offline_baseline.py`, `validation.py` и `requirements.txt`. Данные, ключи, результаты и тесты в архив не включаются. Иван проверяет запуск распакованного архива перед отправкой.
