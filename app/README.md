# Alfa Lab 0.3

Локальная лаборатория команды вокруг конкурсного AutoML-агента. Данные, обучение, сравнение моделей, запуск Qwen и выбор предсказаний доступны в браузере. Python 3.12 и существующих зависимостей проекта достаточно; Node.js не нужен.

## Запуск

На Windows дважды нажмите `app/AlfaLab.exe`. Откроется небольшое окно управления и панель в браузере. В окне можно снова открыть панель или завершить приложение. При закрытии во время обучения появится подтверждение остановки.

EXE — запускатель лаборатории. Держите его в папке `app` существующего проекта: он использует уже настроенное окружение `.venv` и данные проекта. Это не автономный установщик Python и ML-библиотек. Для запуска не нужен Node.js.

Альтернативный запуск — `app/start-app.bat` или команда из корня проекта:

```powershell
.\.venv\Scripts\python.exe app/server.py --open
```

Адрес при запуске через BAT: `http://127.0.0.1:8765/`. Терминал сервера остаётся открытым; дальнейшие операции выполняются в браузере. Если порт занят, используйте `--port 8766`. На Linux: `.venv/bin/python app/server.py --open`. EXE открывает адрес своего сервера автоматически.

## Работа в панели

1. Выберите задачу. Если данные не загружены, нажмите «Загрузить данные».
2. Запустите baseline. Укажите имя, если хотите подписать результат. Лаборатория покажет настоящие этапы и вывод процесса.
3. Запустите Extra Trees для сравнения другой модели на тех же проверочных строках. Заметка сохраняется в истории; алгоритм определяется выбранным рецептом.
4. В «Результатах» сравните локальные метрики. «Лучший в группе» появляется только для сопоставимых собственных запусков на текущих данных.
5. Нажмите «Использовать CSV», чтобы сделать предсказания выбранного запуска текущим `submission.csv`. До этого исходный результат сохраняется. Можно скачать отдельный CSV любого успешно завершённого запуска.

После запуска панель показывает, что получилось и есть ли сопоставимый результат: стартовая точка, улучшение или ухудшение. Сравнение допускается только на текущих данных, с одинаковой метрикой и одинаковыми проверочными строками. Прежний baseline, найденный в файлах задачи, отмечается отдельно от новых запусков панели.

## Выгрузка кнопками

- **«Скачать пакет запуска»** сохраняет ZIP с предсказаниями выбранного запуска `submission.csv`, отчётом `reports.json` и читаемой сводкой `report.html`. Передавать коллеге можно один архив; он добавляется кнопкой импорта без ручной распаковки. Пакет доступен для завершённого локального запуска с проверенным CSV на текущих данных.
- **«Скачать отчёт JSON»** выгружает только сводки экспериментов для импорта в другую лабораторию.
- **«Собрать solution.zip»** создаёт и скачивает конкурсный `solution.zip` из текущего кода проекта. В нём те же разрешённые исходники, которые выбирает `build_submission.py`, с `solution.py` в корне. Данные, `.env`, панель, модели и локальные результаты не включаются. Сборка не означает проверку качества агента.

Все эти действия скачивают файлы на компьютер. Приложение не отправляет архив на конкурсную платформу и не публикует его в интернете.

Кнопка «Остановить» завершает текущую работу. Одновременно выполняется один запуск на лабораторию, чтобы задачи не конкурировали за CPU/RAM. Закрытие вкладки не останавливает обучение; закрытие сервера останавливает работу. После перезапуска история сохраняется, незавершённый запуск помечается прерванным.

## Модели и честное сравнение

Baseline использует существующий HistGradientBoostingRegressor или RandomForestClassifier. Альтернативный рецепт использует ExtraTreesRegressor/Classifier. Оба обучают предобработку только на обучающей части и оцениваются на фиксированном holdout 80/20, seed 42, со стратификацией для классификации. Метрики публичных задач: RMSE и Macro F1.

Для каждого запуска сохраняются модель, гипотеза/заметка, автор, время, метрика, отпечаток данных и проверочных строк, а также фактические предсказания holdout. Финальная модель обучается на всех train-строках. Результаты с разными версиями данных или проверками не объединяются. Совпадение ID в train/test и повторяющиеся строки признаков показаны как диагностические факты, а не доказанная утечка.

Все входы копируются в отдельную папку запуска. Обучение не редактирует исходные CSV. При выборе результата предыдущий текущий CSV сохраняется в резервной копии. Если исходные данные изменились, старый результат нельзя применить к новой версии.

## Qwen из браузера

Заполните локальный `.env` в корне проекта данными организаторов:

```dotenv
OPENAI_API_KEY=...
OPENAI_BASE_URL=...
OPENAI_MODEL=...
```

Ключ не вводится в браузере и не выдаётся через HTTP. Наличие настроек проверяется без API-запроса. Кнопка Qwen запускает существующий `solution.py` на отдельной копии задачи с выбранным лимитом от 1 до 175 минут. Это расходует общий бюджет команды. Указанная гипотеза передаётся в копию описания задачи как направление исследования.

Для исследования доступны stdout/stderr, реальный статус агента, токены при наличии usage, журнал и код сгенерированных экспериментов. `fallback` показывается как резервный CSV, даже если процесс завершился с кодом 0. Метрика не извлекается из произвольного текста Qwen: при отсутствии структурированной проверки в таблице будет прочерк. Успешная проверка CSV подтверждает формат.

Приложение предоставляет только фиксированные действия. Универсального терминала или исполнения произвольной команды из HTTP нет.

## Командные отчёты

В «Результатах» выгрузите отчёт команде или скачайте пакет запуска и передайте файл участнику. Он добавит его кнопкой импорта отчётов. Принимаются JSON и ZIP пакета запуска — распаковывать ZIP вручную не требуется. Из ZIP читается только `reports.json`; предсказания коллеги не заменяют текущий CSV. Совпадение содержимого задачи проверяется по SHA-256; локальные пути на компьютерах могут различаться. Повторный импорт не создаёт копий.

Передаются разрешённые сводки: автор, заметка, модель, метрика, разбиение, статус и время. Датасеты, ключи, модели, код, журналы и CSV-предсказания в пакет отчётов не включаются. Импортированные метрики отмечены как полученные от участника; они не проверены на этом компьютере, не участвуют в автоматическом выборе локального лучшего результата и не заменяют CSV.

Это локальные экземпляры с обменом отчётами. Общего сервера с аккаунтами и автоматической синхронизацией в этой версии нет.

## Где хранятся результаты

По умолчанию: `app/.workspace/`, папка исключена из Git. В ней находятся история, копии данных и предсказания запусков, резервные CSV и импортированные отчёты. При обновлении приложения сохраняйте эту папку. Длительные эксперименты занимают место на диске, поскольку входы копируются для каждого запуска.

Можно указать другие пути:

```powershell
.\.venv\Scripts\python.exe app/server.py --data-dir "D:\Hackathon\data" --state-dir "D:\Hackathon\lab-state"
```

Папка состояния не должна находиться внутри отдельной задачи. Данные обнаруживаются по `task.md` и одному набору train/test/dictionary/sample в каждой папке задачи. CSV свыше 512 МБ и таблицы свыше 512 столбцов не поддерживаются.

Сервер слушает только 127.0.0.1. Изменяющие запросы требуют токен текущего сеанса; посторонние Host/Origin, символические ссылки, junction-папки и произвольные пути отвергаются.

Управление деревом процессов рассчитано на Windows Job Objects и Linux с `/proc`. В ограниченной Linux-среде без `/proc` разрешены только штатные offline-рецепты и подготовка данных; запуск генерирующего код агента блокируется до исполнения. Реальное обучение в ограниченной проверочной среде не требует Qwen.

## Обновление без Git

Дождитесь завершения нужного запуска и закройте старый сервер. Распакуйте новую папку `app` из архива в корень существующего проекта с заменой файлов. Сохраните `app/.workspace/`. Затем откройте `app/AlfaLab.exe`. BAT остаётся альтернативным способом запуска.

Корневой README, зависимости, агент и сборщик конкурсного ZIP не меняются. Панель не входит в `delivery/solution.zip`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s app/tests -v
.\.venv\Scripts\python.exe dev_check.py
```

Часть проверок Windows/Linux containment требует соответствующей ОС и доступного `/proc`. Отсутствующий доступ обозначается пропуском проверки, а не подтверждением работы этой возможности.
