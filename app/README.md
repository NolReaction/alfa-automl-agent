# Alfa Lab 0.5.1

Локальная лаборатория команды вокруг конкурсного AutoML-агента. Данные, автоподбор, обучение отдельных моделей, запуск Qwen и выбор предсказаний доступны в браузере. Python 3.12 и существующих зависимостей проекта достаточно; Node.js не нужен.

## Запуск

На Windows дважды нажмите `app/AlfaLab.exe`. Откроется небольшое окно управления и панель в браузере. В окне можно снова открыть панель или завершить приложение. При закрытии во время обучения появится подтверждение остановки.

EXE — запускатель лаборатории. Держите его в папке `app` существующего проекта: он использует уже настроенное окружение `.venv` и данные проекта. Это не автономный установщик Python и ML-библиотек. Для запуска не нужен Node.js.

Альтернативный запуск — `app/start-app.bat` или команда из корня проекта:

```powershell
.\.venv\Scripts\python.exe app/server.py --open
```

Адрес при запуске через BAT: `http://127.0.0.1:8765/`. Терминал сервера остаётся открытым; дальнейшие операции выполняются в браузере. Если порт занят, используйте `--port 8766`. На Linux: `.venv/bin/python app/server.py --open`. EXE открывает адрес своего сервера автоматически.

## Работа в панели

1. Выберите задачу в списке слева: «Энергопотребление зданий» — регрессия, «Сетевые атаки» — классификация. Если данные не загружены, нажмите «Загрузить данные».
2. Нажмите **«Автоподбор»**. Для первого запуска оставьте автоматическую проверку и лимит 10 минут. Укажите имя, если хотите подписать результат.
3. Дождитесь завершения. В карточке запуска появится таблица попыток с метриками и выбранным победителем. Baseline и ExtraTrees можно запускать отдельно, когда хотите проверить конкретную настройку.
4. В «Результатах» сравните локальные метрики внутри одной группы проверки. У каждой группы свой лучший локальный запуск; оценки разных схем не ранжируются вместе. Прежний отчёт из терминала находится в отдельном свёрнутом блоке.
5. Нажмите «Использовать CSV», чтобы сделать предсказания выбранного запуска текущим `submission.csv`. До этого исходный результат сохраняется. Можно скачать отдельный CSV любого успешно завершённого запуска.

После запуска панель показывает, что получилось и есть ли сопоставимый результат: стартовая точка, улучшение или ухудшение. Сравнение допускается только на текущих данных, с одинаковой метрикой и одинаковыми проверочными строками. Прежний baseline, найденный в файлах задачи, отмечается отдельно от новых запусков панели.

## Где ошибается классификатор

Откройте завершённый запуск задачи «Сетевые атаки». Под общей метрикой появится блок **«Где ошибается модель»**:

- Классы расположены от меньшего F1 к большему. Рядом видно число истинных примеров в проверке и число прогнозов этого класса.
- **«Найдено»** — доля примеров класса, которые модель распознала (recall). **«Точность»** — доля правильных ответов среди прогнозов этого класса (precision).
- **«Чаще всего путает»** показывает направление ошибки: истинный класс → предсказанный. Процент считается внутри истинного класса.
- В свёрнутой **матрице ошибок** строки — истинные классы, столбцы — прогнозы. Цвет нормируется по строке, чтобы редкие классы оставались заметны.

Разбор относится к отложенным строкам, а не скрытому test. Macro F1 усредняет F1 классов с равными весами: класс из 16 примеров тоже влияет на итог, но его оценка чувствительна к нескольким ошибкам. Высокая accuracy не заменяет основную метрику.

Для прежних локальных запусков разбор можно восстановить без обучения, если сохранились проверочные предсказания и прошла проверка их связи с запуском. Один сводный JSON без этих предсказаний не позволяет восстановить матрицу. В импортированных отчётах диагностика остаётся данными участника, не проверенными локально. Подробности сохраняются в выгрузках JSON и HTML.

## Выгрузка кнопками

- **«Скачать пакет запуска»** сохраняет ZIP с предсказаниями выбранного запуска `submission.csv`, отчётом `reports.json` и читаемой сводкой `report.html`. Передавать коллеге можно один архив; он добавляется кнопкой импорта без ручной распаковки. Пакет доступен для завершённого локального запуска с проверенным CSV на текущих данных.
- **«Скачать отчёт JSON»** выгружает только сводки экспериментов для импорта в другую лабораторию.
- **«Собрать solution.zip»** создаёт и скачивает конкурсный `solution.zip` из текущего кода проекта. В нём те же разрешённые исходники, которые выбирает `build_submission.py`, с `solution.py` в корне. Данные, `.env`, панель, модели и локальные результаты не включаются. Сборка не означает проверку качества агента.

Все эти действия скачивают файлы на компьютер. Приложение не отправляет архив на конкурсную платформу и не публикует его в интернете.

Кнопка «Остановить» завершает текущую работу. Одновременно выполняется один запуск на лабораторию, чтобы задачи не конкурировали за CPU/RAM. Закрытие вкладки не останавливает обучение; закрытие сервера останавливает работу. После перезапуска история сохраняется, незавершённый запуск помечается прерванным.

## Автоподбор без API

Один запуск проверяет четыре заранее заданные настройки baseline и ExtraTrees. Он использует то же автономное ядро, что `solution.py --mode offline`; ключ и интернет для обучения не нужны. По умолчанию общий лимит — 10 минут, его можно изменить от 1 до 175 минут.

В таблице попыток видны модель, метрика, время и статус. Победителем становится лучший кандидат среди успешно проверенных за этот запуск. Программа пересчитывает качество по проверочным предсказаниям, а также проверяет формат итогового CSV. Неудачная или худшая попытка не заменяет победителя. Это не обещание улучшить все прежние эксперименты команды.

Если лимит закончился после успешной попытки, показывается **«Лимит времени · лучший сохранён»**. Если ни одна модель не завершилась успешно, запуск сообщает ошибку. Ручная остановка завершает весь запуск; она не равнозначна штатному достижению лимита времени.

Фактическая схема проверки и параметры победителя сохраняются в результате. После завершения CSV можно скачать или выбрать кнопкой **«Использовать CSV»**. Для подробного разбора есть [описание автономного ядра](../docs/offline_automl.md).

## Модели и честное сравнение

Baseline использует существующий HistGradientBoostingRegressor или RandomForestClassifier. Альтернативный рецепт использует ExtraTreesRegressor/Classifier. Оба обучают предобработку только на обучающей части и оцениваются на одинаковых проверочных строках выбранной схемы. Метрики публичных задач: RMSE и Macro F1.

## Эксперименты с настройками

Для отдельного baseline или ExtraTrees в окне запуска раскройте **«Настройки модели»**. Без изменений используются прежние настройки рецепта. Доступные поля зависят от задачи и выбранной модели:

| Модель | Что можно менять |
| --- | --- |
| RandomForest — baseline для сетевых атак | Число и глубину деревьев, минимум строк в листе, долю признаков, веса классов |
| ExtraTrees | Число и глубину деревьев, минимум строк в листе, долю признаков; для классификации — веса классов |
| HistGradientBoosting — baseline для энергопотребления | Число шагов, скорость обучения, число листьев, минимум строк в листе, регуляризацию |

Чтобы продолжить завершённый локальный эксперимент, нажмите **«Изменить настройки»**. Откроется тот же рецепт с его параметрами и схемой проверки. Измените один параметр, добавьте короткую заметку и запустите: появится новая запись, прежний результат сохранится. Сброс в окне возвращает стандартные параметры выбранного рецепта.

Настройки сохраняются в истории, JSON-отчёте и HTML-сводке пакета запуска. Они применяются и при проверке качества, и при финальном обучении на всех данных. У старых запусков без сохранённых параметров панель не придумывает значения. Импортированный отчёт показывает настройки коллеги, но остаётся непроверенным локально результатом.

Параметры относятся к этому запуску Alfa Lab и его CSV. Они не переписывают `offline_baseline.py` или код конкурсного агента внутри `solution.zip`. Перенос подтверждённого улучшения в агента — отдельное изменение кода с проверкой.

Seed 42 и предел в 8 потоков фиксированы. Диапазоны параметров ограничены; произвольный Python-код в эти поля не принимается. Большие модели могут работать дольше. При сравнении схема и проверочные строки остаются прежними: изменение параметров модели не создаёт отдельную группу сравнения.

Один удачный запуск — результат на выбранной проверке. После серии настроек полезно отдельно проверить выбранный вариант на других временных или групповых разбиениях, прежде чем считать улучшение устойчивым.

## Выбор проверки модели

В окне запуска offline-рецепта выберите способ отделить проверочные строки от обучающих:

| Схема | Что проверяем |
| --- | --- |
| Автоматически — только для автоподбора | Для классификации с дублями выбирается групповая проверка; для регрессии с распознанным будущим периодом в test — временная; в остальных случаях — случайная. Причина выбора сохраняется |
| Случайная 80/20 | Прежний способ: фиксированные 20% строк, seed 42, стратификация для классификации |
| По времени — для регрессии | Выберите числовой столбец периода. Последний период идёт на проверку, более ранние — на обучение |
| По группам дублей — для классификации | Строки с одинаковыми исходными признаками попадают в одну часть; ID и правильный ответ не входят в ключ группы |

Для публичной регрессии можно проверить `Year_Factor`: годы 1–4 → год 5. Для публичной классификации — группировку дублей. Выбор опирается на [анализ данных команды](../docs/data_notes.md); схема проверки сама по себе не гарантирует совпадение с устройством скрытого теста.

Групповой режим использует один фиксированный fold с попыткой сохранить доли классов, а не среднее полного кроссвалидационного прогона. Временная и групповая проверка могут выделить больше или меньше 20% строк: панель показывает фактический размер. Если подходящее разбиение невозможно, запуск сообщит причину.

История прежних запусков сохраняется. Старые оценки `0.619640` и `44.651289` относятся к случайной проверке; сравнивайте новые baseline и ExtraTrees внутри одной схемы и группы сравнения. У запуска, в таблице экспериментов и в выгружаемом отчёте указаны способ проверки и его параметры.

Настройка применяется к автоподбору, baseline и ExtraTrees в Alfa Lab. Автоматический выбор не переходит молча на случайную проверку, если корректно разделить группы невозможно: запуск сообщит причину. Запуск Qwen использует цикл конкурсного агента; его сгенерированные эксперименты нужно проверять отдельно.

Проверенные результаты на публичных данных и порядок повторения: [локальная проверка рецептов](../docs/validation_notes.md).

Для offline-рецептов сохраняются сведения о модели, гипотеза/заметка, автор, время, метрика, отпечаток данных и проверочных строк, а также фактические предсказания holdout. Финальная модель обучается на всех train-строках. Результаты с разными версиями данных или проверками не объединяются. Совпадение ID в train/test и повторяющиеся строки признаков показаны как диагностические факты, а не доказанная утечка.

Все входы копируются в отдельную папку запуска. Обучение не редактирует исходные CSV. При выборе результата предыдущий текущий CSV сохраняется в резервной копии. Если исходные данные изменились, старый результат нельзя применить к новой версии.

## Qwen из браузера

Заполните локальный `.env` в корне проекта данными организаторов:

```dotenv
OPENAI_API_KEY=...
OPENAI_BASE_URL=...
OPENAI_MODEL=...
```

Ключ не вводится в браузере и не выдаётся через HTTP. Наличие настроек проверяется без API-запроса. Кнопка Qwen запускает `solution.py --mode llm` на отдельной копии задачи с выбранным лимитом от 1 до 175 минут. Это расходует общий бюджет команды. Указанная гипотеза передаётся в копию описания задачи как направление исследования.

Для исследования доступны stdout/stderr, реальный статус агента, токены при наличии usage, журнал и код сгенерированных экспериментов. `fallback` показывается как резервный CSV, даже если процесс завершился с кодом 0. Метрика не извлекается из произвольного текста Qwen; таблица приложения пока не переносит `best_metric` из исследовательского отчёта в группы сравнения. Для RMSE/Macro F1 ядро Qwen закрепляет holdout, пересчитывает метрику по предсказаниям и сохраняет только улучшения; результат и причины отказа видны в журнале агента. На неизвестной метрике проверяется формат CSV, а качество помечается как непроверенное независимо.

Приложение предоставляет только фиксированные действия. Универсального терминала или исполнения произвольной команды из HTTP нет.

## Командные отчёты

В «Результатах» выгрузите отчёт команде или скачайте пакет запуска и передайте файл участнику. Он добавит его кнопкой импорта отчётов. Принимаются JSON и ZIP пакета запуска — распаковывать ZIP вручную не требуется. Из ZIP читается только `reports.json`; предсказания коллеги не заменяют текущий CSV. Совпадение содержимого задачи проверяется по SHA-256; локальные пути на компьютерах могут различаться. Повторный импорт не создаёт копий.

JSON-отчёт содержит сводки: автор, заметка, сведения о модели, метрика, разбиение, статус и время. Датасеты, ключи, обученные модели, код, журналы и CSV-предсказания в JSON-отчёт не включаются. ZIP запуска дополнительно содержит CSV и HTML-сводку. Импортированные метрики отмечены как полученные от участника; они не проверены на этом компьютере, не участвуют в автоматическом выборе локального лучшего результата и не заменяют CSV.

Это локальные экземпляры с обменом отчётами. Общего сервера с аккаунтами и автоматической синхронизацией в этой версии нет.

## Где хранятся результаты

По умолчанию: `app/.workspace/`, папка исключена из Git. В ней находятся история, копии данных и предсказания запусков, резервные CSV и импортированные отчёты. При обновлении приложения сохраняйте эту папку. Длительные эксперименты занимают место на диске, поскольку входы копируются для каждого запуска.

Можно указать другие пути:

```powershell
.\.venv\Scripts\python.exe app/server.py --data-dir "D:\Hackathon\data" --state-dir "D:\Hackathon\lab-state"
```

Папка состояния не должна находиться внутри отдельной задачи. Данные обнаруживаются по `task.md` и одному набору train/test/dictionary/sample в каждой папке задачи. CSV свыше 512 МБ и таблицы свыше 512 столбцов не поддерживаются.

Сервер слушает только 127.0.0.1. Изменяющие запросы требуют токен текущего сеанса; посторонние Host/Origin, символические ссылки, junction-папки и произвольные пути отвергаются.

Управление деревом процессов рассчитано на Windows Job Objects и Linux с `/proc`. В ограниченной Linux-среде без `/proc` разрешены только штатные offline-рецепты и подготовка данных; запуск генерирующего код агента блокируется до исполнения. Реальное обучение в ограниченной проверочной среде не требует Qwen.

## Обновление без Git

Дождитесь завершения нужного запуска и закройте старый сервер. Обновляйте исходники всего проекта из одной версии архива репозитория: теперь лаборатория использует общие модули из `agent/`. Сохраните свои `.venv`, `.env`, `data/` и `app/.workspace/`. Если изменился `requirements.txt`, установите зависимости по инструкции в корневом README. Затем откройте `app/AlfaLab.exe`. BAT остаётся альтернативным способом запуска.

Панель не входит в `delivery/solution.zip`. Инструкция по её запуску также есть в корневом README; конкурсный агент и его зависимости остаются отдельной частью проекта.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s app/tests -v
.\.venv\Scripts\python.exe dev_check.py
```

Часть проверок Windows/Linux containment требует соответствующей ОС и доступного `/proc`. Отсутствующий доступ обозначается пропуском проверки, а не подтверждением работы этой возможности.

Проверки логики интерфейса запускаются через Node.js, если он установлен, и не требуют npm-пакетов. Без Node.js эти тесты пропускаются; само приложение по-прежнему работает без него.
